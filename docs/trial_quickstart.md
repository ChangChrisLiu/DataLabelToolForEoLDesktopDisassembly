# 试标：D13 扫描仪视角，照着窗口一步步做

这份是"照着做"的流程，一行一个动作，后面写**做完你会看到什么**。每个键、每种情况的完整说明在
[annotation_guide.md](annotation_guide.md)。试标的目的是**找出不顺手的地方**：哪一步卡住、哪个
键别扭、哪里看不懂，记下"哪台机器 / 哪一帧 / 当时在做什么"告诉我。

原则（2026-09-19 定）：**四个视角各自从头标，视角内保持一致**；身份（这是 `ram_module.02`）来自
日志，四个视角共用；形状每个视角自己画。现在先只试 `scan`。

D:\Anaconda\envs\tda\python.exe -m tda.cli app --annotator chang --desktop 13 --view scan

### 两个实例其实是同一个零件？（「合并到…」）

表格有时把一个零件写成两行，程序就建了两个实例，任务卡两个都要。D2 就是这样：第 38 步「Screw Cover」
→ `cover.01`，第 46 步「Front Cover」→ `cover.02`，其实是同一块盖板 —— 第 38 步打开，第 46 步拿走。
在第 37 帧，卡片同时要 `cover.01` 和 `cover.02`。

1. 先把步骤表改对：`Steps` 里第 38 步 `cover.01` 的动词改成 `open`，**先别点 `Apply`**（第 46 步不用动，
   合并时会改）。不改就合并会被拒绝，并说哪几帧对不上："合并后 cover.01 和这些已确认帧对不上（scan 第 38–45 帧：
   确认时有它，合并后按步骤表它已不在画面里）。先在 Steps 把步骤改对，例如那一步的动词（不用先 Apply），
   再「合并到…」：确认框会提供「Apply 并合并」，一次写入"。
2. `Instances` 页右键 `cover.02` →「合并到… / Merge into…」→ 选
   `cover.01 — Screw Cover（of=motherboard_screws；第 38 步 open）`（留下的那个的 `of` 决定合并后的规则边，
   所以选属性对的那个）。
3. 表里有没 Apply 的修改，所以确认框第一行是「Apply 并合并」：Steps 里还有没 Apply 的修改（步骤/动作）。选 Yes
   会先 Apply 这张表、再合并，一次写入；任何一步被拒绝都什么也不写，表里的修改原样留着。下面列出搬什么、丢什么：
   - 搬过去：「形状 7 个（scan 锚在第 37–42、45 帧）」「已确认的行 8 行（scan 第 38–45 帧）」
     「动作 1（第 46 步改成 cover.01）」「冲突记录 5」「层级 1」；
   - 丢掉：「缓存行 36 行（会重新编译）」「手写状态事件 cover.02 第 38 步 closed→open：合并后第 38 步它已经是
     open，这条多余」（你在第 38 帧按 `T` 写的那条，现在由动作本身说了）。
   点 `Yes`。→ 实例表只剩 `cover.01`，会话在同一帧重开，状态行以"已 Apply（步骤/动作）并合并：已把 cover.02
   合并到 cover.01（形状 7、已确认的行 8、动作 1；……）"开头。
4. 结果：`cover.01` 第 37 帧关着、第 38–45 帧开着、第 46 帧起拆走；画过的形状和确认过的行都在 `cover.01`
   上，没有冲突，第 38–48 帧仍是已确认的。（要是第 1 步先单独 `Apply` 再合并，`Apply` 后的后台复检会看到
   `cover.01` 开着却没有形状，把第 38–48 帧打回"需复核"，合并后还得逐帧 `Space`。表里干净时「合并到…」直接
   合并，确认框最后一行是"立即写入，不经 Apply"。）

只能合并同一类；`ls:` 草稿要采纳（`Shift+A`）不能合并；两个在同一帧上都画了形状、或在同一步都有动作，就是
两个零件，会拒绝。`import-logs --force` 重新导入时合并保留（表格里还是两行，导入后仍是 `cover.01`）。

### 零件其实长在另一个零件上（实例表 `Parent`）

`cover.01` 上的：松开只是把线拿出来，第 3 步卡扣跟导风罩一起拆下（第 3 步日志写的是 `open`，已用 `Shift+T`

## 2. 第 42 帧（起点：已经拆完的样子）

D13 的 scan 视角之前已经做过一部分：**机箱范围（ROI）已经存好，机箱 `chassis` 已经画好**。所以一打开
（图：[docs/img/u2b_start.jpg](img/u2b_start.jpg)）：

- 画面自动缩放到机箱范围：一条**紫红色虚线**（黑边衬底，左上角有「机箱范围 ROI」小标签；和机箱边缘
  贴得很近；图：[docs/img/u2g_after_scan42_roi.jpg](img/u2g_after_scan42_roi.jpg)），状态栏右侧写
  `ROI ✓`；机箱上是它已经画好的颜色；
- 任务卡两条：「主板螺丝盖板 cover.02」`待画`，和排在最后的「机箱 chassis」`✔ 已完成`；
- 右上角写"现在：在右边任务卡上单击「主板螺丝盖板 cover.02」开始画（还剩 1 个）"，① 已经打勾。

1. **先核对 ROI**：紫红虚线要包住整个机箱（留一点边）—— 差异图、螺丝检测器和 SAM 的提示框都只在
   这个框里算。**没存 ROI 的视角，检测器不找螺丝**（框照旧来自差异图），存好 ROI 才开始。
   要调：点状态栏的 `ROI ✓`（或左边「机箱范围 ROI」按钮，或 `Shift+R`）。→ 矩形**在原来的位置**带着
   8 个白色小方块出来（图：[docs/img/u2b_roi.jpg](img/u2b_roi.jpg)）：拖边 / 角调整，框里按住整体挪
   → `Q` 保存；不改就按 `Esc`，原来的一点不变。编辑层有没提交的像素时会被挡，先 `Q` 或 `Esc`。
   - **`V` 不是 ROI**：`V` 是「台面框」，给**已经拆下来、放在台面上的零件**拖框用（`R` 是圆形）。ROI 是
     `Shift+R`（左边「机箱范围 ROI」按钮）。
   - 换到一台**还没存 ROI** 的机器时，第一帧会自动出一个**紫红色粗虚线建议框**等你回答
     （图：[docs/img/u2g_after_oak1_42_proposal.jpg](img/u2g_after_oak1_42_proposal.jpg)）：拖白色小方块
     调好，按 `Q` 保存；不想现在管就按 `Esc`（画布下方留一行 `ROI 未确认`，右上角 ① 变成 ⚠，
     不挡你做别的）。
2. 看右边任务卡。顶上一句："第 42 帧（起点，已经拆完的样子）：把这一帧里还看得到的零件都画出来，
   每个都画完整形状（被别的零件挡住的部分也算它的，层级程序会处理）。还剩 1 个，1 个画好了（✔，排在
   最后）"。每一条写着中文名、实例键、日志里的名字、要做什么，右边是状态：
   - `✚ 主板螺丝盖板 cover.02 — 日志：Case cover for motherboard screws [待画]` / 在这一帧画出它的完整形状
   - `✚ 机箱 chassis [✔ 已完成]` —— 画好的也列着，排在没画的后面；单击它会打开已存的形状（见本节末）。

   鼠标**停**在一条上，画面上会用彩色虚线框（黑边衬底）标出它大概在哪，框左上角的小标签写明是什么
   （差异最大处 / 旧草稿 ls:… / 第 N 帧画的形状），只是显示，不会改任何东西。
3. **单击**这一条（单击就行，双击也可以）。→ 马上能看到三处变化
   （图：[docs/img/u2b_editing_empty.jpg](img/u2b_editing_empty.jpg)）：
   - 画布顶上黄字横幅："正在画：主板螺丝盖板 cover.02（日志：Case cover for motherboard screws）—
     用 S 在零件上点一下，或 X 拖框"；
   - 任务卡这一条变黄，状态变成 `✎ 正在画`；
   - 左边「SAM 点选」变成深色：开始画一个零件时，工具切到**记住的 SAM 工具**，默认是 `S`（SAM 点选）；
     你用过 `X`（SAM 框选），下一个零件就从框选开始。中间用画笔、橡皮修边不影响这个记忆。
4. 在盖板上**点一下**（左键加一个点，右键减一个点），或按 `X` 沿盖板外沿**拖一个框**（拖的时候是
   白色虚线框）。画面上的**橙色虚线框「SAM 提示框（程序猜的位置）」**是差异图猜的位置，常常猜错，会和你的点
   一起交给 SAM（要补螺丝的帧上框由螺丝检测器给，标签是「SAM 提示框（检测器：螺丝）」，见第 3 节第 5 步）：
   **永远点零件本身**，框对了你的点就在框里；框不对 —— 第一个点落在框外（离框超过屏幕上约 8 个
   像素），这一次就只用你的点，框自动不用了（状态栏会说），这一帧上它也不会自己再出现，换一帧再回来
   才会；或按 `Shift+C` 换一个框。
   → 出现黄色半透明的形状；横幅变成"… — Q 提交 / Esc 放弃"；左边「提交」有了蓝框。
   不满意：按 `C`（或「换候选」）换 SAM 的另一个答案，共 3 个。
5. 边缘不对：`W` 画笔补、`E` 橡皮擦。笔刷大小用左边滑块，或点一下数字框直接输入（例如 `24`，
   按 `Enter` 确定、`Esc` 取消，之后键盘自动回到画布），键盘 `1` `2`（或 `[` `]`）也行；数字是图像像素，和
   右下角黄标签的 `r=` 是同一个数。`Shift+F` 填内部空洞，`Shift+D` 删碎块。滚轮缩放，
   **鼠标中键拖动平移**（或点左下的小地图）。零件要画**完整轮廓**（被别的零件盖住的部分也算它的）。
   （图：[docs/img/u2b_editing_pixels.jpg](img/u2b_editing_pixels.jpg)）
6. 按 `Q`（或「提交」）。→ 这一条变成 `✔ 已完成`（起点帧上画好的排到后面；每一帧做完的条目
   都留在清单上，标 ✔），横幅消失。
   如果画布下方弹出"面积异常"：确认没画错就再按一次 `Q`，否则 `Esc` 回去改。
7. 两条都是 ✔ 了：卡片顶上写"这一帧的零件都画好了，直接 Space 确认"，右上角写"按 Space 确认整帧"，
   左边「确认整帧」有蓝框。按 `Space`。
   → 自动退到第 41 帧。没通过就不动，原因列在任务卡下面（通常是还有零件没画）。
   挡住 `Space` 的问题在按之前就列在那里：卡片顶上、✔ 条和「现在做什么」都写"还有 N 个问题挡住
   Space"。其中"这一帧有未处理的冲突"是说这一帧确认过的形状后来在别的帧被改了（例如在第 j 帧按
   `Ctrl+Q` 改全部修了它）：单击那一条进 Review → Conflicts（已选中），`K` 保留旧的、`N` 采用新的。

状态栏右侧一直写着 `ROI ✓` / `ROI 未确认` / `无 ROI`。存好的 ROI 是一条**紫红色虚线**，左上角标签

### 提交时选哪个键

| 情况 | 键 / 按钮 |
|---|---|
| 形状从这一帧起变了（绝大多数情况） | `Q`「提交」 |
| 只有这一帧特殊：被手挡住、反光、糊了 | `Alt+Q`「只改这一帧」 |
| 这一整版从一开始就画错了，走过、确认过的帧也要一起改（少用） | `Ctrl+Q`「改全部」 |
| 画布下方弹出"层级"建议（你画的像素落在别的零件里） | 读提示条；一般 `Q`（**只改形状**）。真要改层级才按 `L`，见下面 |

画错了 `Ctrl+Z`「撤销」；不想要这次编辑 `Esc`「放弃编辑」。**有未提交的像素时，翻帧、切视图、
确认都会被挡住**（「确认整帧」按钮也是灰的），状态栏提示先 `Q` 或 `Esc` —— 这是故意的，保证不丢编辑。

**`Q` 是"从这帧起"**：倒序里你走过的帧（帧号比这帧大的）一个像素都不动，确认过的也不会变红；这一帧
和往前的帧用新画的样子。这一帧本来就是这版形状的起点（比如这个零件就是在这一帧画的）时没有走过的帧要
保留，`Q` 就是重画这一版。`Enter`、`Ctrl+K` 和 `Q` 是同一个键。走过的帧没跟着改时，状态栏和画布上会写
"已从这帧起新版本；第 11–14 帧（其中已确认 2 帧）仍是旧样子，要一起改用 Ctrl+Q"：这时直接按
`Ctrl+Q`（不用再点零件），这版形状就也写到那几帧，这一帧不再单独一版（有已确认帧先问："把这版形状也写到
第 11–14 帧（其中已确认 2 帧，会重新检查）？"，再按一次才写入）；`Ctrl+Z` 一次撤回。

`Ctrl+Q`「改全部」改的是这一版用到的每一帧，走过的、确认过的也改。会碰到已确认帧时第一次按只在
画布下方提示条问："改全部会改这一版形状用到的每一帧：第 1–14 帧（共 14 帧），其中已确认的第 12、13 帧会被
重新检查（可能产生冲突）。确定？" —— 再按一次 `Ctrl+Q`（或点「Ctrl+Q 确定改全部」）才写入；`Esc`
取消，画的东西还在。在这版的起点帧上：后面的帧还是上一版时，就像上一段那样把这版也写过去（隔着状态边界 ✂
时不行）；后面没有上一版时它就是 `Q`，状态栏会说。

### 层级建议：`Q` 只改形状，改层级用 `L`

提示条用大白话写：你画到了哪个零件占着的像素（或擦掉了和哪个零件重叠的地方）、`Q` 写什么、`L` 写
什么、谁会被盖住。例如"你画到了「主板螺丝 …」占着的像素……Q = 只改形状，……照样盖着；L = 改层级：
把「…」放到「…」上面（两者重叠处……会被……盖住，整个位姿段都这样）"。

- **`Q` 只改形状**（从这帧起），这是绝大多数情况；`Ctrl+Q`、`Alt+Q` 也只改形状。
- 只有确定"A 就该盖在 B 上面"时按 **`L`**（或提示条上的「L 改层级」）。第一次按只**问**：
  "层级改动作用于整个位姿段：第 1–40 帧，其中已确认的第 39、40 帧会被重新检查（可能产生冲突）。确定？"
  —— 再按一次 `L`（或点「L 确定改层级」）才写入；`Esc` 取消，回到原来的提示条，画的东西还在。
- **层级不是形状版本**：它不能按帧拆分，从这帧起的新版本也拆不了它，对整个位姿段里两个零件都在的每一帧都成立。
  它只把两者**重叠处**的像素换给上面那个，别的零件一个像素都不动。
- 零件和它所在的零件之间（螺丝和机箱、卡扣和主板、装在别的零件上的……）**不会**出层级建议：在机箱上
  画到螺丝那里、或把螺丝擦掉重画，都只是改形状，直接 `Q`。
- 撤销了层级（`Ctrl+Z`）以后，它引起的冲突在后台复检到那几帧、或你回到那几帧（或按 `F5`）时自动关闭
  （输入又和确认时一致了），帧回到已确认，`Space` 可以按。

### 被挡住 / 看不见的零件

**标注时不用管可见性标签**：被别的零件挡住、太小、画面外，编译器都自动算出来；标注模式没有可见性键了
（以前的 `Ctrl+1`–`7`、`Ctrl+V` 搬到了复查的「可见性审查」，见 §4「最后的可见性审查」）。手或工具挡在画面里：
「遮挡」（`O`）把手涂出来。以前手动设过的标签照旧：实例表那一格黄底，画好了却被设成看不见的标 `⚠`，任务卡那一条
写"⚠ 已设为不可见"；不对就 `Ctrl+Z`，或者最后在「可见性审查」里改。

**零件在原位，只是被线挡住了**（线不标注）：形状照样画（这一帧看不到就从别的帧带过来），然后在实例表
选中它按 `` ` `` —— 按一次 = **被线挡住（完全）**：这一帧它的可见部分为空，画布上只剩虚线轮廓；按两次 =
**被线挡住（部分）**：看得见的像素照旧；按三次撤回。实例表那一格写「线挡」/「线半挡」，任务卡那一条写
"⚠ 被线挡住（完全）"，这一条照样算完成；导出时写明是被线缆挡住，完整形状也一起导出。连着好几帧都这样：
`` Ctrl+` `` 选完全/部分/撤回、填"一直到第 N 步"，一次标完（一次撤销）。D2 的例子：前面板接口
`connector.front_panel.01` 插在原位，被风扇线盖住 —— 整个看不见按一次 `` ` ``，露出一半按两次。还没有形状的零件
按 `` ` `` 会被拒绝："先画出它的形状（可以从别的帧带过来），再按 \` 键标被线挡住"。零件合照里 `` ` `` 仍是「看不见」
（不在这张里）。

**零件在机器里，但在这个视角的画面外**（D63 的导风罩在主视角画面外，别的视角可能看得到）：这不是被挡住，没有形状
可画——`` Ctrl+` `` 选第四项「画框外（这个视角拍不到）」、填"一直到第 N 步"（不用先画形状，一次撤销）；任务卡那一条写
「画框外」、算完成，实例表写「框外」，`Space` 不再因为它缺形状被拒。`` ` `` 不会标出画框外，在它上面按 `` ` `` 是撤回。

### 画面里的状态和日志不一样（`T`）

画面里的状态和日志不一样（比如卡扣中途又关上了）：选中它，按 `T` 把这帧的状态改过来；工具会自动在
下一帧恢复原状态，并在任务卡上给出 ✂ 行，在那一帧画这几帧的形状、按 `Q`。不要用 `Ctrl+Q`
改全部去表达状态变化。

D13 的例子：`ram_latch.01` 第 14 步被打开，第 20、21 帧上它又是关着的。

1. 第 21 帧：在实例表点「ram_latch.01」，按 `T`（或实例表下方的状态框选「状态：关上」）。→ 状态栏和
   画布顶上写"内存卡扣 ram_latch.01 在第 21 步：关上（之前为 打开）；第 22 步起恢复 打开。这帧的形状要
   重画：画「关上」后 Q；工具会自动在状态边界切开版本（Ctrl+Z 撤销）"；任务卡多一条 ✂（打开 → 关上）。
2. `PgDn` 到第 20 帧，同样选中按 `T`。→ "……第 20–21 步都是 关上；第 22 步起恢复 打开。这几帧的形状要
   重画：在第 21 步画「关上」后 Q，第 20–21 步都用它；工具会自动在状态边界切开版本"。
3. 回到这一段**最先走到的第 21 帧**（✂ 行）画出关上的样子，按 `Q`：从第 21 帧起是新的一版，第 22 帧
   起打开的样子不动。**提交不会越过状态边界**：工具先在第 19 步把旧版本切开（形状不变），状态栏写
   "已先在第 19 步切开旧版本（形状不变），这次修改只影响第 20、21 步"。（在第 20 帧按 `Q` 只改第 20 帧
   往前：第 21 帧还是打开的样子，它的 ✂ 还开着。）切出来的
   旧版本只是**占位**：第 19 帧的 ✂ 写着"待画：这帧上是另一状态的形状副本，画好后 Q"。那里留下的是打开的
   样子，本来就对 —— 到第 19 帧选中它按 `Ctrl+Shift+K`（这帧就是这个形状），不用重画；不对就画好按 `Q`。
4. 这几帧原来都确认过：第 20、21 帧会出冲突（形状确实变了），在 Review 里按 `N`「采用新的」（或
   `Shift+N` 一次接受）；别的帧形状没变，不会出冲突。状态改了、形状还没画的 ✂，`cli check` 会列成
   `shape_predates_state`（列的是 ✂ 行所在的那一帧；要画哪几帧看按 `T` 后的状态栏）。

日志自己的边界也按这个规矩：第 13、14 帧的卡扣还共用一个版本时（日志第 14 步才打开它），在打开的那一段里
（例如第 20 帧）按 `Q` 重画（改的是第 20 帧往前），工具同样先在第 13 步切开旧版本，第 13 帧的 ✂ 就写"待画：
这帧上是另一状态的形状副本……"，直到在那里画好关着的样子按 `Q`，或形状确实没变按 `Ctrl+Shift+K`。

拆下之前的最后几帧也一样，而且**连着几帧可以一次设完**（D2 的盖板就是这样：日志里没有"打开"，第 46 步
整个拿走，第 38–45 帧画面上都是开着的）。D13 的例子：卡扣第 39–41 帧是关着的，主板第 42 步把它带走。

1. 第 41 帧选中它按 `T`。→ "……在第 41 步：关上（之前为 打开）；第 42 步起是 拆下……"
2. 往前看几帧，第 40、39 帧也是关着的：还在第 41 帧，按 `Ctrl+T`，状态选「关上」，填"一直到第 39 步"，
   `Enter` 确定。→ "内存卡扣 ram_latch.01 第 39–41 步都是 关上；第 42 步起 拆下。这几帧的形状要重画：在第 41 步
   画「关上」后 Q，第 39–41 步都用它；工具会自动在状态边界切开版本"。整段是**一次**操作，`Ctrl+Z` 一次撤回。
3. 在第 41 帧画好按**一次** `Q`。→ "已先在第 38 步切开旧版本（形状不变），这次修改只影响第 39–41 步"。
   这里唯一的 ✂ 行在第 38 帧（"待画：这帧上是另一状态的形状副本……"）：那一帧还是打开的，留下的副本就是打开的
   样子，在第 38 帧按 `Ctrl+Shift+K` 确认即可；不加改动的 `Q` 会被拒绝。

画完以后才发现前面还有几帧也是这样，也不用重画：接着按 `T`（或 `Ctrl+T`），第 38 步切开的那份旧形状
**跟着边界走**，状态栏写"形状版本边界也随之移到第 37 步"，新加进来的帧直接用这一段的形状；副本到了哪一帧，
那一帧的 ✂ 就写"待画"（D2 的盖板：副本是 45 帧开着的样子，到第 37 帧要画关着的盖子，画好 `Q`）。同一个
零件连着几帧按 `T`，状态栏会提醒 `Ctrl+T`；连着三帧，多半是日志漏了这一步的动作 —— 去 Steps 模式补上更稳。
`cli check` 把已确认帧上的副本列成 `cut_copy_in_force`（✂ 那一帧本身仍列为 `shape_predates_state`）。

`T` 只在画面里有这个零件、而且它有两种以上要画的状态时可用（卡扣：关上/打开；螺丝：拧紧/拧松；
大件：装着/挪开）；其它情况状态栏说为什么。"拆下"不能这样设 —— 什么时候拆下由步骤表决定。和步骤表的
动作对不上时（例如说卡扣第 13 帧就开了，可日志第 14 步才"打开"它）会拒绝：去 Steps 模式改动作在
哪一步。步骤表里的重复帧（dupli）跟它重复的那一帧走：要到那一帧去改，恢复也落在重复帧之后。这个视角
没有图像的帧不能改（状态栏指向最近有图像的帧；状态四个视角共用，也可以换个视角）。按错了 `Ctrl+Z`；
再按一次 `T` 也能换回去。

**螺丝其实拧下来了，也是 `Shift+T`。** 戴尔机器的 CPU 散热器螺丝，程序一律当成"拧松后留在零件里"（captive：
拧下那一步只算拧松，螺丝跟着散热器走）。例子是 D3（**已经改好了**）：五颗风扇螺丝其实第 2–6 步就拧下拿走了，改之前

确认过的帧退回待复核）。按错了用 `Ctrl+Z`。别的机器遇到同样的情况照这样改；反过来（拧下后其实留在零件里）：勾 `Removed`，选它按
`Shift+T`（「其实留在零件里」）。改的是实例表里这颗螺丝的 captive，四个视角一起变，`import-logs --force` 重导也保留；
Steps 里有没 Apply 的修改时会先让你 Apply 或 Revert。

### 冲突从哪来、怎么一次解决

冲突 = 你确认过的帧里存着的形状，和现在的标注算出来的不一样了。几乎都来自你自己的两种操作：

- **补零件**：「＋ 添加零件」加的零件出现在已确认帧里，这些帧就回到"需复核"（多了一个零件，等于
  你确认的不是现在这套零件）。小窗会先写出是哪几帧。补画它，再逐帧 `Space`。
- **重画已确认的形状**：比如回到第 41 帧（`ram_latch.01` 这一版的起点）把它重画了 —— 它的形状覆盖第
  17–41 帧，这些确认过的帧就都出冲突（`ram_latch.01` 自己的一条，加上被它挡住的 `motherboard.01` 一条）。单击它开始
  编辑时，状态栏会先说"重画会影响 25 个已确认帧（第 17–41 帧），提交后用 Shift+N 一次接受"。在别的帧上
  `Q` 只改这一帧往前，走过的帧不动；要连走过的帧一起改用 `Ctrl+Q`「改全部」，它先问会碰到哪些已确认帧。
  - 每帧每个零件**只留最新的一条**冲突：分几次提交也不会叠出好几条（以前第 41 帧 `motherboard.01`
    叠了 13 条），但**还是一次画完再提交**省事。
  - 确认过的帧被打回"需复核"后，冲突照样在后台检查出来，不用等你一帧帧翻到；打开视角时也会把所有
    确认过的帧在后台再核对一遍（已经有冲突的帧除外）。
- **给新零件画第一笔**：新零件盖住了已确认帧里的零件（例如第 41 帧的卡扣盖在主板上），被盖住的那个
  零件在这些帧里也会出冲突（主板少了被卡扣盖住的那几块）。一样是 `Shift+N` 一次接受。
- **一次解决**：确定新画的才对，就到 Review 按 `Shift+N`（或「接受全部新值…」）。小窗按零件列出冲突，
  例如 `ram_latch.01 ×25（帧 17–41）`、`motherboard.01 ×25（帧 17–41）`，默认全勾；要保留旧形状的
  零件取消勾选（之后逐条 `K`）。点「接受勾选的 … 个」，鼠标转一会儿，状态栏写"已接受 k 个，仍开放 m 个"。
  被你又改过一次的冲突会自动换成最新的再接受，不用管。状态栏后面还写着"后台复检中 N 帧"时，等它跑完
  可能还会冒出新的冲突（队列上的数会涨），到时候再按一次 `Shift+N`。
- 顺序建议：**先把缺的零件加上、确认过的形状改好，再一路 `Space`**；这样基本不会有冲突。
- **差得很少的不出冲突，用「重签」**：容差以内（边界 2 px 以内的差不算，其余的差不超过 max(面积的 2 %, 20 px)）的变化
  不开冲突，确认过的帧就一直存着旧像素（相邻两个零件互相压着一小条、改层级后留个没人要的小洞），Review 面板下方的
  「重签这一帧」/「重签全部」把这些行改成今天的编译（先告诉你要改几帧再问，先备份，帧仍是已确认，超出容差的照旧是冲突；
  没有快捷键；**撤销不能用 `Ctrl+Z`**，要关掉应用后在命令行 `python -m tda.cli refreeze --desktop 13 --view scan --undo last`），
  `tda.cli check` 最后一行 `stale_within_tolerance` 是还剩几条。

### 最后的可见性审查

标注时不设可见性；一个视角的帧都确认完以后，在 Review 里点「可见性审查」标签页，把这个视角里**不是普通"可见"
的标签逐条过一遍**（每个视角各做一次：`F1`–`F4` 换视角，标签页跟着换）。每一条是一个零件的一段帧，例如
「ram_latch.03 第 1–13 帧 · occluded_full（被硬盘支架挡住，自动）」——「自动」是编译器算的，「手动」是你设过的，
「原因: 线缆」是被线挡住。选中一条，画面跳到那一帧、实例表选中那个零件（OAK / RealSense 上「主视角」小窗也跟着）。
**按键作用于选中的这一整段**（一次撤销）：

- 对：`Space`（`Shift+Space` 一样）。
- 不对：数字键 `1`–`7` 手动设（`1` 可见、`3` 完全遮挡、`4` 画面外……）；`` ` `` 被线挡住（`` Shift+` `` 部分）；
  **`Z` 角度看不到**（`Shift+Z` 部分）——40 帧的一段也只按一次 `Z`。答完自动选下一条，`Ctrl+Z` 撤销。
- 一段里只有某一帧不一样：点面板右上的「按帧」，一行一帧，选那一帧再按；「按段」切回来。上面写「还要审 n 段 / m 帧」。
- 每条写「第 a–b 帧（n 帧）」，最长的一段排最前，上面的表是每个零件在各视角看不见几帧 / 几段；选中一条，下面是它的首、中、尾三帧、**其他视角同样这几步**看得见几帧（看得见的绿底）和建议（例如别的视角看得见、这里没东西挡着 → `Z`），键还是你按。
  理由中途变了就停在那一帧点「从这帧起另算」；答完一段，其他视角同样看不见、还没审、也没手动标过的帧点「同步到其他视角」一起写上（审过的、手动标的都不碰，`Ctrl+Z` 撤销）。

**角度和线缆是两个原因，分开标**：`Z` = 零件在原位、什么也没挡住它，只是这个相机从它的位置看不到（侧面视角常见）；
`` ` `` = 被线盖住了。导出时分别写 `viewpoint` / `cable`。列表空了标签页写「可见性审查完成」；
`tda.cli status --desktop 13` 每个视角写「可见性审查 已审/总数」。
