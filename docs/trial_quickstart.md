# 试标：D13 扫描仪视角，照着窗口一步步做

这份是"照着做"的流程，一行一个动作，后面写**做完你会看到什么**。每个键、每种情况的完整说明在
[annotation_guide.md](annotation_guide.md)。试标的目的是**找出不顺手的地方**：哪一步卡住、哪个
键别扭、哪里看不懂，记下"哪台机器 / 哪一帧 / 当时在做什么"告诉我。

原则（2026-09-19 定）：**四个视角各自从头标，视角内保持一致**；身份（这是 `ram_module.02`）来自
日志，四个视角共用；形状每个视角自己画。现在先只试 `scan`。

---

## 0. 启动

```bat
D:\Anaconda\envs\tda\python.exe -m tda.cli app --annotator chang --desktop 13 --view scan
```

窗口约 1 秒出现。SAM 在后台加载，右下角出现 `SAM ready` 之前，左边的「SAM 点选」「SAM 框选」
是灰的（鼠标停上去或点一下，状态栏会说原因）。螺丝检测器也在后台加载（几秒到二十来秒），第一次打开
一个视角时再在后台把这个视角的每一帧过一遍（42 帧：scan 约 6 秒，oak1 约 8–10 秒，oak2 约 8 秒），

马上就是检测器的框）。这些都不用等，照常开始标（见第 3 节第 5 步）。

**窗口从左到右**（图：[docs/img/u2b_start.jpg](img/u2b_start.jpg)）：

| 位置 | 是什么 | 怎么用 |
|---|---|---|
| 最左 | 时间轴 | 点一帧跳过去 |
| 左二 | **工具面板** | 上面是工具，中间是笔刷大小，下面是操作。**所有操作按钮都在这里**；点按钮 = 按那个键，按钮上写着键。深色底黄字的是当前工具；**蓝框的是下一步最该按的**；灰的现在不能用，鼠标停上去或点一下，状态栏说为什么。**最底下是小地图**：整张图的缩略图，蓝框是你现在看的范围，点一下 / 拖动就把视野移过去 |

| 右上 | **现在做什么** | 黄底一行 = 下一步按什么；下面 ①–⑤ 是这一帧的五步，▶ 是现在这步；「快捷键」点开是这个模式能用的全部键 |
| 右中 | **任务卡** | 这一帧要画的零件清单（见第 3 节） |
| 右下 | 实例表 | 这一帧画面里有的零件 |

看不懂下一步时，**先看右上角黄底那一行**。

小屏幕（1280×720）也能用：工具面板和「现在做什么」放不下时可以用滚轮滚动，小地图固定在面板最底下

### 两个实例其实是同一个零件？（「合并到…」）

表格有时把一个零件写成两行，程序就建了两个实例，任务卡两个都要。D2 就是这样：第 38 步「Screw Cover」
→ `cover.01`，第 46 步「Front Cover」→ `cover.02`，其实是同一块盖板 —— 第 38 步打开，第 46 步拿走。
在第 37 帧，卡片同时要 `cover.01` 和 `cover.02`。

1. 先把步骤表改对：`Steps` 里第 38 步 `cover.01` 的动词改成 `open`，**先别点 `Apply`**（第 46 步不用动，
   合并时会改）。不改就合并会被拒绝，并说哪几帧对不上："合并后 cover.01 和这些已确认帧对不上（scan 第 38–45 帧：
   确认时有它，合并后按步骤表它已不在画面里）。先在 Steps 把步骤改对，例如那一步的动词（不用先 Apply），
   再「合并到…」：确认框会提供「Apply 并合并」，一次写入"。
2. `Instances` 页右键 `cover.02` →「合并到… / Merge into…」→ 选
   `cover.01 — Screw Cover（of=motherboard_screws；第 38 步 open）`（留下的那个的 `of` 决定合并后的规则边，
   所以选属性对的那个）。
3. 表里有没 Apply 的修改，所以确认框第一行是「Apply 并合并」：Steps 里还有没 Apply 的修改（步骤/动作）。选 Yes
   会先 Apply 这张表、再合并，一次写入；任何一步被拒绝都什么也不写，表里的修改原样留着。下面列出搬什么、丢什么：
   - 搬过去：「形状 7 个（scan 锚在第 37–42、45 帧）」「已确认的行 8 行（scan 第 38–45 帧）」
     「动作 1（第 46 步改成 cover.01）」「冲突记录 5」「层级 1」；
   - 丢掉：「缓存行 36 行（会重新编译）」「手写状态事件 cover.02 第 38 步 closed→open：合并后第 38 步它已经是
     open，这条多余」（你在第 38 帧按 `T` 写的那条，现在由动作本身说了）。
   点 `Yes`。→ 实例表只剩 `cover.01`，会话在同一帧重开，状态行以"已 Apply（步骤/动作）并合并：已把 cover.02
   合并到 cover.01（形状 7、已确认的行 8、动作 1；……）"开头。
4. 结果：`cover.01` 第 37 帧关着、第 38–45 帧开着、第 46 帧起拆走；画过的形状和确认过的行都在 `cover.01`
   上，没有冲突，第 38–48 帧仍是已确认的。（要是第 1 步先单独 `Apply` 再合并，`Apply` 后的后台复检会看到
   `cover.01` 开着却没有形状，把第 38–48 帧打回"需复核"，合并后还得逐帧 `Space`。表里干净时「合并到…」直接
   合并，确认框最后一行是"立即写入，不经 Apply"。）

只能合并同一类；`ls:` 草稿要采纳（`Shift+A`）不能合并；两个在同一帧上都画了形状、或在同一步都有动作，就是
两个零件，会拒绝。`import-logs --force` 重新导入时合并保留（表格里还是两行，导入后仍是 `cover.01`）。

## 2. 第 42 帧（起点：已经拆完的样子）

D13 的 scan 视角之前已经做过一部分：**机箱范围（ROI）已经存好，机箱 `chassis` 已经画好**。所以一打开
（图：[docs/img/u2b_start.jpg](img/u2b_start.jpg)）：

- 画面自动缩放到机箱范围：一条**紫红色虚线**（黑边衬底，左上角有「机箱范围 ROI」小标签；和机箱边缘
  贴得很近；图：[docs/img/u2g_after_scan42_roi.jpg](img/u2g_after_scan42_roi.jpg)），状态栏右侧写
  `ROI ✓`；机箱上是它已经画好的颜色；
- 任务卡两条：「主板螺丝盖板 cover.02」`待画`，和排在最后的「机箱 chassis」`✔ 已完成`；
- 右上角写"现在：在右边任务卡上单击「主板螺丝盖板 cover.02」开始画（还剩 1 个）"，① 已经打勾。

1. **先核对 ROI**：紫红虚线要包住整个机箱（留一点边）—— 差异图、螺丝检测器和 SAM 的提示框都只在
   这个框里算。**没存 ROI 的视角，检测器不找螺丝**（框照旧来自差异图），存好 ROI 才开始。
   要调：点状态栏的 `ROI ✓`（或左边「机箱范围 ROI」按钮，或 `Shift+R`）。→ 矩形**在原来的位置**带着
   8 个白色小方块出来（图：[docs/img/u2b_roi.jpg](img/u2b_roi.jpg)）：拖边 / 角调整，框里按住整体挪
   → `Enter` 保存；不改就按 `Esc`，原来的一点不变。编辑层有没提交的像素时会被挡，先 `Enter` 或 `Esc`。
   - **`R` 不是 ROI**：`R` 是「台面框」，给**已经拆下来、放在台面上的零件**拖框用。ROI 是
     `Shift+R`（左边「机箱范围 ROI」按钮）。
   - 换到一台**还没存 ROI** 的机器时，第一帧会自动出一个**紫红色粗虚线建议框**等你回答
     （图：[docs/img/u2g_after_oak1_42_proposal.jpg](img/u2g_after_oak1_42_proposal.jpg)）：拖白色小方块
     调好，按 `Enter` 保存；不想现在管就按 `Esc`（画布下方留一行 `ROI 未确认`，右上角 ① 变成 ⚠，
     不挡你做别的）。
2. 看右边任务卡。顶上一句："第 42 帧（起点，已经拆完的样子）：把这一帧里还看得到的零件都画出来，
   每个都画完整形状（被别的零件挡住的部分也算它的，层级程序会处理）。还剩 1 个，1 个画好了（✔，排在
   最后）"。每一条写着中文名、实例键、日志里的名字、要做什么，右边是状态：
   - `✚ 主板螺丝盖板 cover.02 — 日志：Case cover for motherboard screws [待画]` / 在这一帧画出它的完整形状
   - `✚ 机箱 chassis [✔ 已完成]` —— 画好的也列着，排在没画的后面；单击它会打开已存的形状（见本节末）。

   鼠标**停**在一条上，画面上会用彩色虚线框（黑边衬底）标出它大概在哪，框左上角的小标签写明是什么
   （差异最大处 / 旧草稿 ls:… / 第 N 帧画的形状），只是显示，不会改任何东西。
3. **单击**这一条（单击就行，双击也可以）。→ 马上能看到三处变化
   （图：[docs/img/u2b_editing_empty.jpg](img/u2b_editing_empty.jpg)）：
   - 画布顶上黄字横幅："正在画：主板螺丝盖板 cover.02（日志：Case cover for motherboard screws）—
     用 S 在零件上点一下，或 X 拖框"；
   - 任务卡这一条变黄，状态变成 `✎ 正在画`；
   - 左边「SAM 点选」变成深色：开始画一个零件时，工具切到**记住的 SAM 工具**，默认是 `S`（SAM 点选）；
     你用过 `X`（SAM 框选），下一个零件就从框选开始。中间用画笔、橡皮修边不影响这个记忆。
4. 在盖板上**点一下**（左键加一个点，右键减一个点），或按 `X` 沿盖板外沿**拖一个框**（拖的时候是
   白色虚线框）。画面上的**橙色虚线框「SAM 提示框（程序猜的位置）」**是差异图猜的位置，常常猜错，会和你的点
   一起交给 SAM（要补螺丝的帧上框由螺丝检测器给，标签是「SAM 提示框（检测器：螺丝）」，见第 3 节第 5 步）：
   **永远点零件本身**，框对了你的点就在框里；框不对 —— 第一个点落在框外（离框超过屏幕上约 8 个
   像素），这一次就只用你的点，框自动不用了（状态栏会说），这一帧上它也不会自己再出现，换一帧再回来
   才会；或按 `Shift+C` 换一个框。
   → 出现黄色半透明的形状；横幅变成"… — Enter 提交 / Esc 放弃"；左边「提交」有了蓝框。
   不满意：按 `C`（或「换候选」）换 SAM 的另一个答案，共 3 个。
5. 边缘不对：`B` 画笔补、`E` 橡皮擦。笔刷大小用左边滑块，或点一下数字框直接输入（例如 `24`，
   按 `Enter` 确定、`Esc` 取消，之后键盘自动回到画布），键盘 `[` `]` 也行；数字是图像像素，和
   右下角黄标签的 `r=` 是同一个数。`Shift+F` 填内部空洞，`Shift+D` 删碎块。滚轮缩放，
   **鼠标中键拖动平移**（或点左下的小地图）。零件要画**完整轮廓**（被别的零件盖住的部分也算它的）。
   （图：[docs/img/u2b_editing_pixels.jpg](img/u2b_editing_pixels.jpg)）
6. 按 `Enter`（或「提交」）。→ 这一条变成 `✔ 已完成`（起点帧上画好的排到后面；每一帧做完的条目
   都留在清单上，标 ✔），横幅消失。
   如果画布下方弹出"面积异常"：确认没画错就再按一次 `Enter`，否则 `Esc` 回去改。
7. 两条都是 ✔ 了：卡片顶上写"这一帧的零件都画好了，直接 Space 确认"，右上角写"按 Space 确认整帧"，
   左边「确认整帧」有蓝框。按 `Space`。
   → 自动退到第 41 帧。没通过就不动，原因列在任务卡下面（通常是还有零件没画）。
   挡住 `Space` 的问题在按之前就列在那里：卡片顶上、✔ 条和「现在做什么」都写"还有 N 个问题挡住
   Space"。其中"这一帧有未处理的冲突"是说这一帧确认过的形状后来在别的帧被改了（例如在第 j 帧按
   `Enter` 修了它）：单击那一条进 Review → Conflicts（已选中），`K` 保留旧的、`N` 采用新的。

状态栏右侧一直写着 `ROI ✓` / `ROI 未确认` / `无 ROI`。存好的 ROI 是一条**紫红色虚线**，左上角标签
「机箱范围 ROI」（和其它图层一样，按 `A` 可以关掉，标签一起关）。左下小地图的**蓝框**只是"现在看的范围"，不是 ROI。

**点开一个已经画好的零件**（例如单击 ✔ 的「机箱 chassis」）：画布上是已存的形状，横幅写"这是已存的形状：
要改就画，改完 Enter；不改按 Esc"。没动过的时候「提交」是灰的 —— 不改就 `Esc`，或者直接点下一条。

## 3. 之后每一帧（第 41 → 1 帧）：通常只多一个零件

1. 看任务卡顶上一句，它按清单里的条目说话：
   - 有 ✚ 条："第 j 帧：比第 j+1 帧多了下面这些零件（刚被拆掉的，要把它画回去）"
     （图：[docs/img/u2g_after_scan41_hover.jpg](img/u2g_after_scan41_hover.jpg)，鼠标停在任务卡那一条上
     时带标签的虚线框）；
   - 只有 ≡ 条："这一帧只有状态变化（拧紧/插上…），不用画，直接 Space"；
   - 只有 ✂ 条："下面这些零件的形状从这一帧起变了（画这一帧的新样子，Ctrl+K 提交）"；
   - 几种都有：列出各有几个，例如"1 个要画回去、1 个形状变了"。
2. 找不到零件在哪：
   - 鼠标停在任务卡那一条上 —— 每个框左上角的标签写着它是什么：橙色「差异最大处（SAM 提示框）」是
     差异图给 SAM 的提示框（变化最大的地方，也是猜的；这一帧不给框、或你点在框外拒掉了它时，这个橙框
     也不显示；框是检测器给的时候写「检测器：螺丝（SAM 提示框）」），蓝色「旧草稿 ls:…」是这一段里
     同类零件的旧草稿（离橙色框最近的至多 5 个），绿色「第 N 帧画的形状」是它在别的帧画过的形状；

### 提交时选哪个键

| 情况 | 键 / 按钮 |
|---|---|
| 这个零件的形状一直就是这样（绝大多数情况） | `Enter`「提交」 |
| 只有这一帧特殊：被手挡住、反光、糊了 | `Alt+Enter`「只改这一帧」 |
| 形状从这一帧起真的变了：盖子掀开、线被拨到一边 | `Ctrl+K`「从这帧起新版本」 |
| 画布下方弹出"层级"建议（你画的像素落在别的零件里） | 读提示条；一般 `Enter`（**只改形状**）。真要改层级才按 `L`，见下面 |

画错了 `Ctrl+Z`「撤销」；不想要这次编辑 `Esc`「放弃编辑」。**有未提交的像素时，翻帧、切视图、
确认都会被挡住**（「确认整帧」按钮也是灰的），状态栏提示先 `Enter` 或 `Esc` —— 这是故意的，保证不丢编辑。

`Ctrl+K` 只有在这一帧**不是**这版形状的起点时才拆得出新版本。这一帧本来就是起点（比如这个零件只在
这一帧画过），`Ctrl+K` 没东西可拆，等于重画这一版，状态栏会写"这一帧就是这版形状的起点：Ctrl+K 等于
重画这一版，没有拆分"。

### 层级建议：`Enter` 只改形状，改层级用 `L`

提示条用大白话写：你画到了哪个零件占着的像素（或擦掉了和哪个零件重叠的地方）、`Enter` 写什么、`L` 写
什么、谁会被盖住。例如"你画到了「主板螺丝 …」占着的像素……Enter = 只改形状，……照样盖着；L = 改层级：
把「…」放到「…」上面（两者重叠处……会被……盖住，整个位姿段都这样）"。

- **`Enter` 只改形状**，这是绝大多数情况；`Ctrl+K`、`Alt+Enter` 也只改形状。
- 只有确定"A 就该盖在 B 上面"时按 **`L`**（或提示条上的「L 改层级」）。第一次按只**问**：
  "层级改动作用于整个位姿段：第 1–40 帧，其中已确认的第 39、40 帧会被重新检查（可能产生冲突）。确定？"
  —— 再按一次 `L`（或点「L 确定改层级」）才写入；`Esc` 取消，回到原来的提示条，画的东西还在。
- **层级不是形状版本**：它不能按帧拆分，`Ctrl+K` 也拆不了它，对整个位姿段里两个零件都在的每一帧都成立。
  它只把两者**重叠处**的像素换给上面那个，别的零件一个像素都不动。
- 零件和它所在的零件之间（螺丝和机箱、卡扣和主板、装在别的零件上的……）**不会**出层级建议：在机箱上
  画到螺丝那里、或把螺丝擦掉重画，都只是改形状，直接 `Enter`。
- 撤销了层级（`Ctrl+Z`）以后，它引起的冲突在后台复检到那几帧、或你回到那几帧（或按 `F5`）时自动关闭
  （输入又和确认时一致了），帧回到已确认，`Space` 可以按。

### 被挡住 / 看不见的零件

在实例表选中实例后按数字键设可见性：`1` 可见、`2` 部分遮挡、`3` 完全遮挡、`4` 画面外、`5` 太小、
`6` 很小但可见、`7` 运动模糊。手或工具挡在画面里：「遮挡」（`O`）把手涂出来。

按了数字键**一定看得见**：状态栏和画布顶上会写例如"机箱 chassis：这一帧的可见性 → 画面外（Ctrl+Z
撤销）"；实例表里这一格变成黄底（这一帧手动设过）。一个**画好了的**零件被设成 `3` 完全遮挡或
`4` 画面外，这一帧就不显示它的形状 —— 实例表那一格标 `⚠`，任务卡那一条写"⚠ 已设为不可见"。不是故意
的就 `Ctrl+Z`，或选中后按 `1` 改回可见。没选中任何零件时按数字键，状态栏会提醒先在实例表点一行。

### 画面里的状态和日志不一样（`T`）

画面里的状态和日志不一样（比如卡扣中途又关上了）：选中它，按 `T` 把这帧的状态改过来；工具会自动在
下一帧恢复原状态，并在任务卡上给出 ✂ 行，用 `Ctrl+K` 画这几帧的形状。不要用 `Enter` 重画已确认的
形状去表达状态变化。

D13 的例子：`ram_latch.01` 第 14 步被打开，第 20、21 帧上它又是关着的。

1. 第 21 帧：在实例表点「ram_latch.01」，按 `T`（或实例表下方的状态框选「状态：关上」）。→ 状态栏和
   画布顶上写"内存卡扣 ram_latch.01 在第 21 步：关上（之前为 打开）；第 22 步起恢复 打开。这帧的形状要
   重画：画「关上」后 Ctrl+K；工具会自动在状态边界切开版本（Ctrl+Z 撤销）"；任务卡多一条 ✂（打开 → 关上）。
2. `PgDn` 到第 20 帧，同样选中按 `T`。→ "……第 20–21 步都是 关上；第 22 步起恢复 打开。这几帧的形状要
   重画：在第 20–21 步任一帧画「关上」后 Enter（第 21 步是 ✂ 行，那里用 Ctrl+K）……"。
3. 在这一段**任一帧**画出关上的样子：第 21 帧（✂ 行）按 `Ctrl+K`，或第 20 帧按 `Enter`，结果一样。
   **提交不会越过状态边界**：工具先在第 19 步把旧版本切开（形状不变）。第 21 帧 `Ctrl+K` 后状态栏写
   "已先在第 19 步切开旧版本（形状不变），这次修改只影响第 20、21 步"；第 20 帧 `Enter` 后写"已先在第 19 步
   切开旧版本（形状不变），新版本只到第 21 步，后面的帧保持原来的形状，这次修改只影响第 20、21 步"。切出来的
   旧版本只是**占位**：第 19 帧的 ✂ 写着"待画：这帧上是另一状态的形状副本，画好后 Ctrl+K"。那里留下的是打开的
   样子，本来就对 —— 到第 19 帧选中它按 `Ctrl+Shift+K`（这帧就是这个形状），不用重画；不对就画好按 `Ctrl+K`。
   （在第 21 帧按 `Enter` 会被拒绝：那一帧本身就是边界，`Enter` 会把第 22 步以后的形状一起改掉。）
4. 这几帧原来都确认过：第 20、21 帧会出冲突（形状确实变了），在 Review 里按 `N`「采用新的」（或
   `Shift+N` 一次接受）；别的帧形状没变，不会出冲突。状态改了、形状还没画的 ✂，`cli check` 会列成
   `shape_predates_state`（列的是 ✂ 行所在的那一帧；要画哪几帧看按 `T` 后的状态栏）。

日志自己的边界也按这个规矩：第 13、14 帧的卡扣还共用一个版本时（日志第 14 步才打开它），在打开的那一段里
（例如第 20 帧）按 `Enter` 重画，工具同样先在第 13 步切开旧版本，第 13 帧的 ✂ 就写"待画：这帧上是另一状态的
形状副本……"，直到在那里画好关着的样子按 `Ctrl+K`，或形状确实没变按 `Ctrl+Shift+K`。

拆下之前的最后几帧也一样，而且**连着几帧可以一次设完**（D2 的盖板就是这样：日志里没有"打开"，第 46 步
整个拿走，第 38–45 帧画面上都是开着的）。D13 的例子：卡扣第 39–41 帧是关着的，主板第 42 步把它带走。

1. 第 41 帧选中它按 `T`。→ "……在第 41 步：关上（之前为 打开）；第 42 步起是 拆下……"
2. 往前看几帧，第 40、39 帧也是关着的：还在第 41 帧，按 `Ctrl+T`，状态选「关上」，填"一直到第 39 步"，
   `Enter` 确定。→ "内存卡扣 ram_latch.01 第 39–41 步都是 关上；第 42 步起 拆下。这几帧的形状要重画：在第 39–41 步
   任一帧画「关上」后 Enter；工具会自动在状态边界切开版本"。整段是**一次**操作，`Ctrl+Z` 一次撤回。
3. 在第 41 帧画好按**一次** `Enter`。→ "已先在第 38 步切开旧版本（形状不变），这次修改只影响第 39–41 步"。
   这里唯一的 ✂ 行在第 38 帧（"待画：这帧上是另一状态的形状副本……"）：那一帧还是打开的，留下的副本就是打开的
   样子，在第 38 帧按 `Ctrl+Shift+K` 确认即可；不加改动的 `Ctrl+K` 会被拒绝。

画完以后才发现前面还有几帧也是这样，也不用重画：接着按 `T`（或 `Ctrl+T`），第 38 步切开的那份旧形状
**跟着边界走**，状态栏写"形状版本边界也随之移到第 37 步"，新加进来的帧直接用这一段的形状；副本到了哪一帧，
那一帧的 ✂ 就写"待画"（D2 的盖板：副本是 45 帧开着的样子，到第 37 帧要画关着的盖子，画好 `Ctrl+K`）。同一个
零件连着几帧按 `T`，状态栏会提醒 `Ctrl+T`；连着三帧，多半是日志漏了这一步的动作 —— 去 Steps 模式补上更稳。
`cli check` 把已确认帧上的副本列成 `cut_copy_in_force`（✂ 那一帧本身仍列为 `shape_predates_state`）。

`T` 只在画面里有这个零件、而且它有两种以上要画的状态时可用（卡扣：关上/打开；螺丝：拧紧/拧松；
大件：装着/挪开）；其它情况状态栏说为什么。"拆下"不能这样设 —— 什么时候拆下由步骤表决定。和步骤表的
动作对不上时（例如说卡扣第 13 帧就开了，可日志第 14 步才"打开"它）会拒绝：去 Steps 模式改动作在
哪一步。步骤表里的重复帧（dupli）跟它重复的那一帧走：要到那一帧去改，恢复也落在重复帧之后。这个视角
没有图像的帧不能改（状态栏指向最近有图像的帧；状态四个视角共用，也可以换个视角）。按错了 `Ctrl+Z`；
再按一次 `T` 也能换回去。

### 盖板/卡扣其实被拆走了（`Shift+T`）

D2 第 48 帧的任务卡要画 cover.01（日志「Screw Cover」）等六个零件，可它们都在零件堆里：日志写的是"打开"。
这种条目都写着"画面里没有它了？Shift+T：其实拆下来了"：在实例表点它（或单击那条），按 `Shift+T`。→ 状态栏写
"主板螺丝盖板 cover.01 在第 38 步是拆下的（不是打开）：从第 38 步起它不在机箱里了（Ctrl+Z 撤销）"，从第 38 帧
起卡片不再要它（画过的，状态栏另说"这些帧上它的形状不再使用（k 帧）"）；六个按完，第 48 帧只剩机箱。改的是
步骤表那一步的动词，四个视角一起变。拆错了：勾实例表 `Removed`，选它再按 `Shift+T`（「其实只是打开了」）。

## 4. 走完之后：Review

1. 点顶部 `Review`。→ 左边的画图工具和笔刷大小收起来了（复查模式画布只读），只剩「接受这一帧
   Enter」「返工 R」「保留旧的（冲突）K」「采用新的（冲突）N」「接受全部新值… Shift+N」和「差异图 D」，
   小地图还在最底下；右上角写复查的键。
2. 右下四个队列：`Conflicts`（`K` 保留旧的 / `N` 采用新的，选中一条冲突后这两个按钮才亮）、
   `Needs review`、`Missing shape`、`Unexplained`（确认时还有没人认领的变化区域，多半是漏标了零件）。
3. 选中一条按 `R`（或「返工」）回到那一帧返工，或 `Enter`（「接受这一帧」）接受。
   （图：[docs/img/u2b_review.jpg](img/u2b_review.jpg)；1280×720：
   [docs/img/u2b_review_1280.jpg](img/u2b_review_1280.jpg)）

### 冲突从哪来、怎么一次解决

冲突 = 你确认过的帧里存着的形状，和现在的标注算出来的不一样了。几乎都来自你自己的两种操作：

- **补零件**：「＋ 添加零件」加的零件出现在已确认帧里，这些帧就回到"需复核"（多了一个零件，等于
  你确认的不是现在这套零件）。小窗会先写出是哪几帧。补画它，再逐帧 `Space`。
- **重画已确认的形状**：比如在第 41 帧把 `ram_latch.01` 重画了 —— 它的形状覆盖第 17–41 帧，这些
  确认过的帧就都出冲突（`ram_latch.01` 自己的一条，加上被它挡住的 `motherboard.01` 一条）。单击它开始
  编辑时，状态栏会先说"重画会影响 25 个已确认帧（第 17–41 帧），提交后用 Shift+N 一次接受"。
  - 每帧每个零件**只留最新的一条**冲突：分几次提交也不会叠出好几条（以前第 41 帧 `motherboard.01`
    叠了 13 条），但**还是一次画完再提交**省事。
  - 确认过的帧被打回"需复核"后，冲突照样在后台检查出来，不用等你一帧帧翻到；打开视角时也会把所有
    确认过的帧在后台再核对一遍（已经有冲突的帧除外）。
- **给新零件画第一笔**：新零件盖住了已确认帧里的零件（例如第 41 帧的卡扣盖在主板上），被盖住的那个
  零件在这些帧里也会出冲突（主板少了被卡扣盖住的那几块）。一样是 `Shift+N` 一次接受。
- **一次解决**：确定新画的才对，就到 Review 按 `Shift+N`（或「接受全部新值…」）。小窗按零件列出冲突，
  例如 `ram_latch.01 ×25（帧 17–41）`、`motherboard.01 ×25（帧 17–41）`，默认全勾；要保留旧形状的
  零件取消勾选（之后逐条 `K`）。点「接受勾选的 … 个」，鼠标转一会儿，状态栏写"已接受 k 个，仍开放 m 个"。
  被你又改过一次的冲突会自动换成最新的再接受，不用管。状态栏后面还写着"后台复检中 N 帧"时，等它跑完
  可能还会冒出新的冲突（队列上的数会涨），到时候再按一次 `Shift+N`。
- 顺序建议：**先把缺的零件加上、确认过的形状改好，再一路 `Space`**；这样基本不会有冲突。

## 4.5 零件合照（拆完后零件摆在桌上拍的照片）

每台拆完后，所有拆下来的零件摆在桌上用两台 OAK 和 RealSense 各拍了几张（每张之间重新摆过）。这些
**不是拆解步骤**，是单独的三个视图：顶部 `零件合照·OAK1 (F6)` / `·OAK2 (F7)` / `·RealSense (F8)`，
或 `python -m tda.cli app --annotator chang --desktop 13 --view cmp_oak1`。

- 窗口标题和任务卡写着「零件合照 OAK1 第 1/5 张：把这张里看得到的零件都画出来；不在这张里的点「看不见」」。
  打开在第 1 张，`Space` 确认后到**下一张**，`PgUp`/`PgDn` 换张。
- 任务卡列的是**拆解最后已经拆下来的零件**（螺丝、接口、线不列：桌上分不清是哪一颗/哪一根；内存卡扣、
  CPU 压杆跟着主板，不单独列）。在这张里看得到的：单击这一条，和平时一样画整件（S/X/B/Enter）；每张单独
  画，画在这张上的形状不会跑到别的张。**这张里没有的**：右键这一条选「看不见（不在这张里）」，或按 `I`；
  标错了再右键「撤回」/再按 `I`，或 `Ctrl+Z`；标了「看不见」又画了它，「看不见」自动取消（同一次 `Ctrl+Z`）。

- 照片里有、卡上没有的零件（日志没写它，例如一颗铜柱）：Steps →「＋ 添加零件」，「拆下于第 __ 步」填它

- 这里没有状态（`T`）、没有 ✂ / `Ctrl+K`、没有差异图和 `Tab` 对比、没有机箱 ROI（整张图都是范围）、

  那一步的帧上去改）：按了状态栏说为什么。零件压在一起时层级照常用 `L` / `Ctrl+↑↓`。

- 进度：`tda.cli status` 表下面单独一段「零件合照」；导出 `tda.cli export-coco --desktops 13
  --view components` 每个相机一个文件（`coco_cmp_oak1.json` …，`split: components`，零件都写

## 7. 已知情况

- **SAM 加载失败**时右下角写"SAM 加载失败：原因（F5 重试）"，`S` / `X` 是灰的，「现在做什么」写
  "SAM 没加载：用 Y 圆形 / B 画笔 / P 多边形"。按 `F5` 重新加载一次（加载中再按不会重复加载）。
  2026-10-12 那次是 SAM 和螺丝检测器同时导入 torch 卡死（`_DeadlockError`）；现在两个模型按顺序加载，
  SAM 先。
- **层级只用 `L` 改，`Enter` 只改形状**（第 3 节"层级建议"）。`L` 第一次按先写明影响第几帧到第几帧、
  哪些已确认会重新检查，再按一次才改。零件和它所在的零件之间（螺丝 / 机箱、卡扣 / 主板）不出层级建议。
- **冲突会自己关**：引起冲突的改动撤销了（输入又和确认时一致），那几帧的冲突自动关闭、回到已确认。
- **冲突不再叠、能一次接受**（第 4 节「冲突从哪来」）：每帧每个零件只留最新的一条；重画已确认的形状前
  状态栏说会影响几个已确认帧；「＋ 添加零件」说会让哪几帧回到"需复核"；Review 里 `Shift+N` 按零件一次
  接受。
- `Esc` 是分层的：没画完的多边形 / 圆形 → 旧草稿预览 → `L` 问的那句（层级确认）→ 面积提示 → ROI 矩形 →
  台面框 → 编辑层，一次退一层
  （多边形没画完时 `Enter` 也先填上它，`Alt+Enter`、`Ctrl+K`、`Space` 等它画完）。
- 按了键没反应：多半是焦点在某个输入框里，点一下画布再按，状态栏也会提示一次（点回画布后这行
  提示自动消失）。
- 灰掉的按钮点一下，状态栏写它为什么现在不能用。
- D64 的自动 ROI 不对：建议框开着时直接拖一个框（或拖白色小方块），`Enter` 保存；已经按过 `Esc`
  才要 `Shift+R`。自动没找到机箱时（例如 rs）建议框是整幅图，`Enter` 存不下，也是直接拖一个框。
  D63 第 31→32 步机箱被转了 90°：画布下方会出现
  "可能的机箱移动"提示条，点接受（或 `Ctrl+Shift+B`）；切分后另一段的形状要重画，ROI 重新问。
- OAK / RealSense 视角（`F2`–`F4`）流程和 `scan` 一样，每个视角各自从头画。
- `Shift+A`：编辑某个零件时把鼠标指在它上面按一下，旧 Label Studio 草稿以淡蓝色预览出现，
  `Enter` 采纳、`Esc` 取消；`Shift+C`：换 SAM 的提示框（检测器找到的其它螺丝在前，差异图的在后）。
- 螺丝检测器的设置在 `configs/detector.yaml`（哪些视角、哪类零件、用哪个模型：`backend: rfdetr`，原来的
  YOLO 还在文件里，改两行就换回去）。它用不了时（例如没有 GPU、模型文件坏了）日志写一行原因，框就全部
  来自差异图，别的照常。
- 请顺手记时间：一台机器 scan 视角从头到尾用了多久、哪类零件最费时间——排期要用。
