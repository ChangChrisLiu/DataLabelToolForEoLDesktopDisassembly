## 0. 一页摘要（TL;DR）

- **项目**：66 台二手台式机（Dell / HP 为主）的逐步拆解数据集，目标 CVPR 2027（截稿 2026-11-16 AoE）。
  每台机器被人手一步步拆开，每一步后四台相机各拍一张：结构光扫描仪俯视 1600×1600（**主视角 `scan`**）、
  两台 OAK-D（`oak1` 近俯视 12 MP、`oak2` 斜视）、RealSense（`rs` 1280×720）。另有「零件合照」

- **现在到哪了**：`scan` 视角 2 800 帧里 **2 440 帧已人工确认**（66 台里 50 多台全做完，见 §7）；

## 4. 数据模型（读数据前必须懂的语义）

### 4.1 步、动作、实例

- `step(desktop, step, step_type, raw_name, dupli, notes)`：`step_type` ∈ initial / normal / compound / reorient / failed / auxiliary / ignore / dupli。
  `raw_name` 是 Drive 表原文。`reorient` = 机箱换了拍摄方向（新位姿段）。
- `action(desktop, step, idx, target, verb, tool, direction, result, …)`：一步可有多个动作（compound 行拆开后）。
  动词（`taxonomy.yaml verbs`）：`unscrew`（螺丝）、`disconnect`（接头）、`open`（卡扣 / 压杆 / 盖板）、`release`（线夹 / 线缆）、
  `remove`、`displace`（拿出来但还在机箱范围内 / 挪了位置）、`reorient`（chassis）。`target` 以 `?` 结尾 = 还没解析的占位（D8 / D35 / D62 还有）。
- `instance(desktop, key, cls, attrs_json, parent, attached, mounted_on, fastens, socket_host, cable, …)`：
  键形如 `screw.motherboard.03`、`connector.front_panel.02`、`cover.01`、`ram_latch.05`；`attrs_json` 带 `kind` / `role` / `of` / `sheet_no` /
  `captive`（螺丝拧下后仍留在零件里，随零件一起走）/ `added_by`（标注员手加的「日志没写的零件」）等。
  `parent + attached=1` = 随父零件一起离开（级联）；`fastens` = 螺丝固定的零件；`socket_host` = 接头插在哪个零件上；`cable` = 虚拟线缆节点。
  `ls:…` 键 = Label Studio 草稿；`ctx.<cls>.NN` = ROI 之外的「框外零件」（独立编译组）。
- 状态：`state_event(desktop, step, target, attr, old, new, auto)`，`auto=1` 由动作推出，`auto=0` 为人工（`T` / `Ctrl+T` 断言、
  初始状态、`absent_from_start`「这台没有这个零件」）。某帧 k 的零件状态 = 把该零件 step ≤ k 的事件按序重放（`tda.core.states`）。
  每类的状态集在 `taxonomy.yaml classes.<cls>.states`，`needs_mask` 说明哪些状态要画形状（拆下的零件不画；台面上的零件另有「台面框」）。
- 隐含规则（导入时自动生成，都可被标注员覆盖）：硬盘架自带卡扣 `drive_latch`（U20）；散热器家族的风扇螺丝 captive（Dell / HP 冷却器，见 §7.3 裁定）；
  插座压杆、内存卡扣挂在主板上。

### 4.2 帧、位姿段、层级、形状

- `frame(desktop, step, view, path, missing, review_status, pose_segment, aux_json …)`：`review_status` ∈ unlabeled / needs_review / verified；
  `missing=1` 的帧没有照片（任何读图都应跳过）。
- `pose_segment(desktop, view, seg, start_step, end_step, ref_step, roi_json, …)`：相机或机箱姿态不变的一段步；形状按段存，换段要重画；
  `roi_json` 是该段的感兴趣区域（扫描仪 1600×1600 里机箱所在矩形）。
- `zorder(desktop, view, pose_segment, order_json)`：该段的全局层级（底 → 顶，`[instance, part]` 对）；画出来的顺序 = 新画的在上，
  机箱 / 主板是地板层（U17）。**已知系统性问题**：倒序画时压杆 / 内存卡扣常在它扣住的零件之下（压杆 57/57、内存卡扣 714/724 反序）——
  用户决定**留到数据处理阶段**再统一处理，已有工具分支（§7.4）。
- `shape_keyframe(id, desktop, view, instance, pose_segment, anchor_step, placement, geom_type, source, …)` + `shape_part(keyframe_id, idx, name, rle_json, box_json)`：
  **amodal 形状**（整件，含被遮部分）。关键帧 j 覆盖同段内 `(上一个关键帧, anchor_step_j]` 的帧（倒序画，往前延伸）。
  `source` ∈ manual / cut / ls …。`rle_json` 是 COCO RLE（`{"size":[H,W],"counts":"…"}`）。
- `frame_override(desktop, step, view, instance, visible_rle_json, visibility, occluder)`：单帧覆盖。`visibility` ∈ visible / partial /
  occluded_full / out_of_view …；`occluder` ∈ `cable`（被线挡住）/ `other_unlabeled`（被没标的东西挡住）/ `viewpoint`（**角度看不到**：在画面里但这个角度看不见）；
  `out_of_view` 且无像素 = **画框外**（零件存在、不在这个视角的画面里，U39）。
- `pair_override`：标注员用 `L` 指定的两零件层级覆盖（目前 0 行）。

### 4.3 真值表（编译结果）与复核

- `compiled_mask(desktop, step, view, instance, visible_rle_json, occlusion_ratio, visibility, placement, status, input_hash, verified_by, verified_at, geom_type, box_json)`：
  编译器（`tda.core.compiler`）把该帧每个在场零件的 amodal 形状按层级叠加，上层减掉下层 → **可见掩码**；`status`：`verified`（人确认过、冻结）或缓存。
  `visibility` 由遮挡比例和覆盖得出；完全被挡的零件保留 amodal。**只有 `status='verified'` 的行是真值**；导出默认只取它们。
- `conflict`：冻结行与今天的重编译不一致（超过容差）时开给人裁决（Review → Conflicts，K/N）；`refreeze` 处理容差内的差别。
- `frame_digest`、`recheck_queue`：复检机制内部表。`frame_note`：标注员的帧说明。`op_log`：**每一次编辑都有一行**（含逆操作），可追溯。
- `relation(desktop, type, target, blocker, necessity, mode, status …)`：拆解先后约束图（spec §7），大多是推断的 `proposed`，尚未人工确认。

### 4.4 常用读法（SQL / Python）

只读打开：`sqlite3.connect("file:D:/DataSet/annotations/tda.sqlite?mode=ro", uri=True)`（或先用 backup API 复制一份再读）。

```sql
-- 某台某视角每帧的已确认可见掩码
SELECT step, instance, visible_rle_json, box_json, visibility, occlusion_ratio
FROM compiled_mask WHERE desktop=13 AND view='scan' AND status='verified' ORDER BY step, instance;

-- 零件元数据
SELECT key, cls, attrs_json, parent, attached, fastens, socket_host FROM instance WHERE desktop=13 AND key NOT LIKE 'ls:%';

-- 某帧的 amodal 形状：找该段里 anchor_step >= k 的最小关键帧
SELECT k.instance, p.rle_json FROM shape_keyframe k JOIN shape_part p ON p.keyframe_id=k.id
WHERE k.desktop=13 AND k.view='scan' AND k.instance='psu.01' AND k.anchor_step>=20 ORDER BY k.anchor_step LIMIT 1;

-- 每步的动作与状态变化
SELECT s.step, s.raw_name, a.target, a.verb FROM step s LEFT JOIN action a USING(desktop, step) WHERE s.desktop=13 ORDER BY s.step, a.idx;
SELECT step, target, attr, old, new FROM state_event WHERE desktop=13 ORDER BY step;
```

Python 层：`tda.pipeline.open_db` / `tda.core.db.Db`（`instances(d)`, `actions(d)`, `frames_for(d, view)`），
`tda.core.states.state_at(...)`，`tda.core.export.coco.export_coco(...)`。**不要用 tda 代码打开线上库写东西**（schema 迁移、锁）。

## 5. 导出与 HuggingFace 准备

推荐以 **扫描仪视角（scan）** 为第一版发布：它是唯一有人工确认真值的视角（2 440 帧 / 50 多台），分辨率最高、无操作员遮挡。

1. 先复制库：`python -c "import sqlite3; ..."`（backup API）到 `D:\DataSet\.cache\tmp\hf\tda.sqlite`，之后所有导出都指 `--db` 到副本。
2. 排除未完成 / 有冲突的台（`cli status`、`cli check`）：目前 D29 有 5 个待裁决冲突；D34/D36/D48/D50–52/D55/D56/D61–D66 未做完；D1 扫描仪缺 9 步。
3. 用 `scripts/export_scanpack.py`（最完整：原图 + 标签图 + COCO + 元数据 + README；`exports/scanpack_2026-10-26` 是 10 台的样例）或
   `cli export-coco --view scan --desktops …`（COCO json，含 `amodal_segmentation` / `amodal_bbox`、crowd 行、`attributes.context` 框外零件）。
   VLM 层：`cli export-vlm --view scan --tasks V1,…`。
4. 建议的 HF 结构：按台分 `D<nn>/`，`images/`（P_0 原图或缓存副本）、`labels/`（16 位实例 id 图）、`annotations.json`（COCO）、
   `sequence.json`（步、动作、状态时间线）、`instances.json`；顶层 `taxonomy.yaml` 副本、`README`、`manifest.json`（sha256）。

## 8. 安全规则（接手者必须遵守）

1. 原始盘只读（只有 `TDA_backups` 由程序写）。所有新文件、缓存、临时目录只能在 `D:`（C: 盘不新建任何东西）。

   `D:\DataSet\.cache\tmp\<task>\` → 只在副本上跑。程序开着时（进程命令行含 `tda.cli app`）连 `cli check` 也不要对线上库跑。
3. 若确需改线上库：程序关闭 → 先备份到 `TDA_backups\tda_pre_<说明>_<日期>.sqlite` → 走程序自己的路径（Steps 面板 API、`commit_verb_fix`、
   `commit_captive_fix`、`assert_state_range`、`mark_present` …），每次写一条 `op_log` 注记 → 之后 `cli check`。本会话的脚本范本在控制方的 scratchpad，
   模式是：dry-run 默认、`--apply` 才写、psutil 按 argv 令牌检测程序进程、`BEGIN IMMEDIATE` 探锁。
4. **永远不要** `import-logs --force` D13（两处动词没有 op 记录）、D42（通用接头按出现顺序编号，`connector.04` 有关键帧）、D36（第 2 步重定向不会被重放）。

5. D2 由用户自己检查，不要动。D27 / D28 保持用户的标注。
6. 改 Drive 表的本地副本时用字节级替换（保留 CRLF），改完提醒用户在 Drive 上同步。
