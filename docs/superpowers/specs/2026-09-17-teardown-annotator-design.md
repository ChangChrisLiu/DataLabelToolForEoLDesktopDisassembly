## 0. 摘要

构建一个运行在本工作站（RTX 5090 / 63 GB / Windows 11）上的 **PySide6 本地一体化标注工具**，为 66 台台式机拆解序列生成：实例掩码（可见 + 近似完整形状）、零件状态、步骤动作、物理约束图，并程序化导出 COCO 与 VLM 训练/评测数据。核心思路：

1. **倒序 + 图层模型**做传播：从拆解末帧往回标，每步只"装回"发生变化的零件，下层可见区域自动计算。
2. **真值是逐帧物化并人工确认的掩码表**，图层模型只是生成器；后续修改绝不静默覆盖已确认的帧。
3. **四个视角各自从头标注，视角内保持一致**（v1.5）：身份、状态机、约束来自步骤表，四个视角共用；形状、层级、位姿段、遮挡每个视角自己的一套，用同一个倒序流程画。扫描仪仍是最先标、最清晰的视角，但**不假设**它的标注能自动变成其他视角的标注——遮挡差别太大，实测也不支持（见 §2.5）。
4. **结构化标注是唯一事实来源**，VLM 文本全部由它生成，答案可程序校验。
5. **约束 = 物理必要性**，由属性规则 + 机型族模板生成、人工确认；实际拆解顺序只用于校验。
6. **先把 66 台全部标完，再划分数据集**；尽早训练模型辅助标注。

## 1. 目标、范围与优先级

### 1.1 目标

- **CV**：四视角实例分割/检测（23 类 + 属性），含小零件（螺丝、卡扣、接口）；状态识别；`detached` 零件识别。
- **约束**：每台机器一张带物理原因的约束图，可计算任一状态下的合法动作集合。
- **VLM**：理解（看到什么、状态、已完成的历史、进度）+ 推理（刚做了什么、现在能做什么/为什么不能、下一步、剩余计划、计划验证、跨视角一致性）。
- **可报告的质量**：逐帧确认率、双标一致性、模型辅助效率（初稿 vs 终稿）。

### 1.2 范围

**v1 包含**：66 台机器 Disassemble 序列（约 2,830 步）× {扫描仪, OAK1, OAK2, RealSense}。

**v1 不包含**：Side view 文件夹（Components 文件夹自 v1.10 起作为零件合照，§3.2b）、房间视频、128 张单反照片、机器人数据、网页界面、多人同时在线。

### 1.3 优先级

| 级别 | 内容 |
|---|---|
| **P0** | 扫描仪 gold（66 台）；步骤/动作/状态；约束图；模型训练闭环；OAK1 gold（先测试机型族）；OAK2 silver（含堆放区框）；RealSense bronze；COCO 导出；VLM P0 任务 + 零样本评测；**9/30 前一次端到端演练**（D13：标注 → COCO → VLM JSONL → 零样本评测） |
| **P1** | OAK1 全量 gold；OAK2 堆放区掩码核验；VLM P1 任务、人类基线、微调一个开源 VLM；双标一致性 |

### 2.2 统一索引

- **帧键**：`(desktop_id, step_k, view)`；`step_k` 是**逻辑步**。OAK 相机1 的拍摄按时间戳排序就是 Drive 记录的**行**；**`dupli` 行不是步**（v1.25，U25）：它是把上一行的状态又拍了一遍，所以逻辑步 = 记录的行去掉 `dupli` 行后**连续重编号**（扫描仪自己的编号本来就不数它们）。行 `r` 属于步 `r − #(dupli 行 ≤ r)`。
- **对齐规则**：OAK1/OAK2 按文件名时间戳配对；RealSense 按文件夹编号 + 文件时间对齐；三者先按行对齐，再按上式收拢——`dupli` 行的那张照片是它所重复那一步的**额外一张**（`aux.extra_shots`：`path`、`src_step_dir`、`ts`、`row`；不是 app 显示的帧，`load-index` 原样写进 `frame.aux_json`）；某视角那一步自己没拍到时，`dupli` 那张顶上做帧。`oak.<d>.dupli_replaces: [行]` 声明某个 `dupli` 是重拍（原来那张拍坏了：零件被拿起、扫描仪的蓝光照在台上），则重拍那张做帧、原来那张做额外一张。**扫描仪**按自己的文件夹编号：`RGB<n>1` 属于步 `n − #(重复文件夹 ≤ n)`，重复文件夹是该步的额外一张（那一步别无扫描时顶上做帧，`replacing_folders` 同上）；哪些文件夹是重复的（扫描仪也拍了的 `dupli` 行、重扫）逐台写在 `scan.<d>.duplicate_folders`（`[]` = 扫描仪跳过了全部 `dupli` 行），由 `scan-align` 排序、看图确认。扫描仪跳过了一个**真实的步**（D41、D61）写 `scan.<d>.skipped_steps: [k]`：第 k 步没有扫描帧，从那里起每个文件夹晚一步（第 b 个文件夹落在第 b 个没跳过的步上），k 算作声明缺失。这条规则被**断言**：除声明缺失的步外每一步都要有扫描帧、每个文件夹都要落到一步上，否则 `MISMATCH`；有 `dupli` 行却没有声明的，同样逐台报出。`missing_steps` 写的是收拢后的步。Drive 记录导入同样去掉 `dupli` 行、后面的行重编号（§2.3）。`build-index` 从 Drive 表读 `dupli` 行（`--logs`）；索引文件 v3，v1/v2 的文件 `load-index` 拒收。`build-index` 覆盖前把原来的索引和报告留成 `<名>_v<版本>_<YYYYMMDD>.<扩展名>`（如 `index_v2_20261024.json`、`index_report_v2_20261024.md`），同名同内容的不再复制。
- **相机1 的行序与零件合照**（v1.25 第二轮）：行默认按拍摄时间排；`oak.<d>.cam1_order: folder` 让行按相机1 文件夹号排（D60：两台相机的时钟都把 004 排在 003 前，但 002/003 是风扇提起、004 是风扇已拆，扫描仪也如此——行跟文件夹号）。`oak.<d>.gallery_captures: [文件夹]` 声明相机1 的某张拍的是拆下来的零件摆在一起、不是哪一行（D1 的 040）：它不算行，OAK1/OAK2（时间戳配对）和 RealSense（同号文件夹或指向它的 `rs_extra_from`）的那张都成为对应合照视图的第 `1000 + 文件夹号` 张（`aux.sequence_capture` 记来源），与 §3.2b 步骤表合照行的 `1000 + 步号` 同一编号区。
- **照片换了步，工作跟着照片走**（v1.25）：`load-index` 比较库里每个序列视角的照片在哪一步、新索引把它放在哪一步；换了步的，关键帧（含 Label Studio 草稿）的锚点、帧行上人写的列（`review_status` 等）、帧级输入（可见性覆盖、实例标记、遮挡层、相似变换）、位姿断点和位姿段的参考 / 范围步一起搬过去，编译结果等派生行删掉重编；没有照片的旧步（缺帧）跟着前面最近的有照片的步走、夹在新步数内。两个旧步落到同一新步时（`dupli` 那张成了额外一张），本步自己那张照片的东西优先：额外一张的帧行上，只有 `review_status`（这一步做到哪了）搬过去——新步没有的才搬、有的算作丢弃并报出；照片本身的列（手/工具入画、成像质量、操作进行中、台面）说的是那张照片，留在额外一张上并报出（"photo column(s) left behind on an extra shot"，v1.25 第三轮）；同一实例的关键帧不重复；画在额外一张上的 Label Studio 草稿，本步照片已有同一标签的就丢掉并计数（否则这一步会显示两套）；落到已有断点上的位姿断点计数。**手写的状态事件**（`state_event.auto = 0`）跟着步骤表走，步骤表跟着相机1 的行走，所以按 `oak1` 的换步搬（`auto = 1` 的由 `import-logs` 重新生成）。`op_log` 是历史记录，payload 里的步号保持写入时的值：撤销栈只在内存里、换台即清空，按 `(步, 目标)` 重放的 Shift+T 修正对不上会报 "not matched"、不会改错地方；线上换号前先跑只读的 `python scripts/precheck_index_moves.py`（已确认帧、已确认编译行、Shift+T 修正、非 LS 的证据步关系是阻塞项，最后一行 `OK` / `NOT OK`；手写事件、`commit_keyframe`、人写的帧列只列出）。整台拒绝（`PhotoMoveConflict`，什么也不写）的两种情况：涉及**已确认帧**；某张照片在新索引的这个视角里**已经没有了**（既不是帧也不是额外一张，如 D1 的 040 去了合照）而上面有工作——挪到邻步就落在别的照片上了。拒绝后提示是"处理这些帧上的工作再 `load-index`"，不是重建索引。`load-index` 记下装入的索引收拢了哪些 `dupli` 行（`desktop.meta.index_dupli_rows`）；**`import-logs` 只在库里的帧按这张表的收拢编号装过时才写**：表有 `dupli` 行而帧是 U25 之前装的、或收拢的行不一样（`load-index` 被拒、失败或没跑），整台拒绝、什么也不写，提示先 `load-index`；没有帧的台不受影响。`import-ls` 也按索引把图片名里的文件夹号换成步（`FolderSteps`；`--desktops` 只重导这几台）；同一步上先导本步照片的任务，额外一张上画的、本步照片已有同一标签的草稿不导（计数 `extra_shot_drafts_skipped` / `_kept`）。

### 2.3 步骤表导入

- 每行生成 `Step`（原始名、原始工具、备注）——`dupli` 行除外（v1.25）：它不是步，丢掉，后面的行连续重编号；它的备注写到它重复的那一步上（「(dupli row 30) …」），它的序号照样参加序号检查。重新导入的台不再有 `dupli` 类型的步（旧库里已有的照旧能读）。
- 从原始名解析出 0..n 个 `Action` 草稿：目标（实例或虚拟节点）、动词、工具（§6 映射）。
- 步骤类型：`initial`（第 1 步，0 动作）、`dupli`（v1.25 起不再产生；旧库里的照旧 0 动作）、`compound`（≥2 动作）、`failed`（有动作、无状态变化）、`auxiliary`（挪开障碍物以露出目标，目标可以是虚拟节点 `cable:*`）、`reorient`（翻转机箱，触发位姿断开）、`ignore`（如 "all components (final layout)"）。

### 2.4 本地缓存、选图与 ROI

- **缓存**：所需图像复制到 `D:\DataSet\cache\<view>\D<nn>\s<kkk>.<ext>`（约 27 GB）。扫描仪 1600² 与 RealSense 1280×720 直接使用；OAK 12MP 生成 ROI 裁剪缓存与金字塔。
- **扫描仪选图**：默认 `P_0`；自动检查曝光（均值/饱和比例）与相对连拍中值的偏差（手入镜），异常时改选连拍中最接近中值且清晰度最高的一张，并记录；可人工改选。
- **ROI**：每台机器每个视角有**机箱 ROI**（自动建议 + 人工确认），以及可选的**桌面 ROI**（放置已拆零件的区域，主要 OAK2）。**掩码一律按原图坐标存储**，ROI 只是显示与推理窗口。

### 2.5 几何

- **帧内配准（同视角相邻步）**：
  - **MVP（扫描仪）**：恒等变换；机箱被翻转由步骤类型 `reorient` 或人工标记触发位姿断开。

### 3.2 实例身份

- **身份由步骤表决定**：`instance_key` = 类别 + 角色 + 同类序号（按首次被操作的逻辑步排序），不依赖记录中的编号。
- **图像中"哪一颗是 3 号"**：MVP 在扫描仪上叠加第 k−1/k 帧差分热图由人点选；P1 起自动把本步目标匹配到变化斑块。不脱落螺丝差分弱时人工点选。
- **四视角同一身份**：第 k 步变化的实例在所有视角是同一物体——身份由任务卡给出，不靠几何。同类多实例（4 根内存、6 颗主板螺丝）靠**时间**区分：哪一步消失的是哪一个，由该视角自己的帧间差分指出（v1.5：不再用跨视角单应投影）。
- **不脱落螺丝 `captive`（v1.17，U14）**：在本工具里 `captive` 的意思是"拧下（`unscrew`）不让它离开机箱"——拧下后 `loosened`、留在原位，随 `parent`（`attached`）一起拆下（§3.3）；不是在说螺丝的机械结构。导入时按启发式猜（戴尔的 CPU 散热器螺丝一律 captive，`captive_source=heuristic`；判断零件身份时用的也是这个猜测），有的机器猜错：D3 的五颗风扇螺丝第 2–6 步就拧下拿走了，任务卡却在第 7–15 帧要它们；D2 的确实留在风扇里。日志分不出，只有画面能：标注模式里选中螺丝按 `Shift+T`（实例表按钮、工具面板「其实拆下」同一个槽），captive 的显示「其实拧下来了」，否则「其实留在零件里」；只给日志里有成功 `unscrew` 的真实螺丝。写入走 S1 的实例编辑：`captive` + `captive_source=manual`；改成 captive 时 `parent` 为空就取 `fastens` 所指零件，并勾 `attached`；改成非 captive 时取消 `attached`，`parent` 保留（翻回来时用）。一条 `captive_fix` op 带逆操作（撤销恢复这条记录和日志），重编自动事件、重盖 graph 元数据；从它的 unscrew 那一步起，所有视角（零件合照全部）里已确认的帧进复检：确认时画着它、现在算已拿走的开冲突（再按一次翻回去时，签名行又对上的帧上那个冲突会关闭），现在要它而没有的退回待复核，状态栏写数目。拒绝：不是螺丝、`ls:` 草稿、日志里没拧下它、要留在零件里却没有 `fastens`/`parent`、之后有接不上的手工状态（T）、会新增 S1 问题、Steps 里有未 Apply 的修改、零件合照、正在画它（未提交的像素）。`import-logs --force` 时按键把替换前实例表里的值盖过启发式（撤销过的不算；与启发式一致的手工值仍记为 manual），在推断 `parent` 之前，一条 `replay_captive` op 分"保留 / 表格已一致 / 对不上（原因）"。

  什么都不写，提示先 `build-index`。
- **步骤表里的合照行**：`ignore` 且名字是 "all components" 的一行（D66 第 13 步）：步号与类型不变，它的 oak1/oak2/rs
  照片成为对应合照视图的第 `1000 + 步号` 张（D66：1013；`aux.sheet_step` 记来源）。用步号定号，Components 文件夹
  自己的照片（1..N）永远碰不到它、以后出现文件夹也不会挪动它；界面按位置数张（第 k/N 张）。序列里这一步的帧行删掉；
  有人标过的帧（确认、LS 草稿、锚在这一步的形状、覆盖/遮挡/冲突、已确认的编译行）不动并报告，未确认的编译行等是缓存，
  随帧删除。`load-index` 与 `import-logs` 都做、幂等（第二次运行不再报告"移动"）、不碰序列帧与标注；重新加载时保留量得的尺寸。
- **重新加载不挪动别人的工作**：新索引在某张的号上给了另一张照片、或不再有这张（文件夹删了/少了），而这张上有工作
  （上面的定义，加上这张位姿段里的任何形状）时，这台机器整台失败、什么都不写，信息写明哪张、上面有什么；没人碰过的张
  改指新照片（量得的尺寸作废，`build-cache` 重新复制）或删掉（连同空的位姿段）。追加的张照常加入。
- **每张一个位姿段** `[k, k]`，ROI = 整张图（`load-index` 写入）。各张之间零件重新摆过，一张上画的形状、层级、
  两两层级覆盖都只属于这一张；不问机箱 ROI，没有台面 ROI。
- **画什么**：本机**最后一步**时状态为 `removed` 的实例，去掉 `connector` / `cable` / `screw`（摆在桌上分不出是

  `state = removed`、`placement = on_bench`。这一张里没有的零件标「看不见」：该帧该实例 `visibility =
  out_of_view` 且无像素 —— 合照帧上它等于"已处理"，不报 `missing_shape`（序列帧上照旧报）；在合照帧上给标了
  「看不见」的零件提交形状，同一个 op 里取消这个标签。
- **日志里没有、照片里有的零件**：§3.2a「＋ 添加零件」多一项「拆下于第 __ 步」（不挂在别的零件上的默认最后一步；
  挂在别的零件上、随它离开的留空），存为该步的手工事件 `→removed`、`in_chassis→on_bench`（`evidence_view =
  s1:added`，属于这次添加：删除/撤销随它走，`import-logs --adopt-extras` 把它和初始状态一起交给表格、撤销时
  一起放回）。起始帧（`initial`）与重复帧（`dupli`）不能填：前者那时零件都还在，后者和它前面那一帧是同一个样子，
  拒绝时指出该填哪一步；默认值是最后一个能填的步。序列在那步之前要它，合照列出它；挂在父零件上又单独拆下的不再
  `attached`（它已经先出来了），拆下步不得晚于父零件离开。添加对话框的"会让哪些已确认帧回到需复核"两类视图都算。
- **没有序列语义**：没有起点帧、没有对照帧（差异图、提示框、`Tab` 闪回都没有）、没有 dupli / ✂ 行、没有状态

  `Shift+N` 照常。在序列与合照之间切换视图时回到上次在那一边的帧（第一次进合照是第 1 张），同一边内保持帧号。
- **界面**：`F6`–`F8` 或 `cli app --view cmp_oak1`；窗口标题与任务卡写「零件合照 OAK1 第 k/N 张：把这张里看得到

  `I` 标「看不见」/撤回；状态栏「零件合照·OAK1」，时间轴「第 k 张」。
- **导出与检查**：`export-coco --view cmp_oak1|…|components` 每视图一个文件，`info.split = components`，图像
  `extra` 写 `shot`（帧号）、`source`（原图路径）、`sheet_step`（来自步骤表行时）；`export-vlm` 不出合照；`cli check`
  （按"张"计）、`status`（序列表下面单列一段）包含合照；步骤表行移进合照后又被改了类型/名字的，`cli check` 把那张
  报为问题（`sheet_shot_without_its_row`，放在最前；不自动挪回：那张上可能有工作）。`build-cache` 的合照帧取自
  数据库（它才知道步骤表行的照片；`--db` 优先于 `paths.yaml`），帧换了照片时重新复制。
- **量得的尺寸属于照片，不属于帧号**（所有视图）：重新加载时帧行仍指向同一个文件才保留 `hw`/`hw_source`/

  变成 missing 的行只留推断尺寸（`hw_source = inferred`）。

### 3.2c 框外零件（context object，v1.18）

用户（2026-10-17）：有的帧里，机器的 ROI 外面有谁也没列过的东西（另一个零件放在旁边、无关的物件），要起个名字单独画，
**和主标注分开**：不进步骤表、任务卡、状态机、关系、检测器/差异图的猜测，也不挡 `Space`。掩码本来就不按 ROI 裁
（只有 `export-coco --roi-crop` 裁），缺的是这个对象本身。

- **就是一个实例**（`Db.instances` 照常返回）：键 `ctx.<class>.NN`（序号在框外零件里按类别接续，不和机器的零件
  一起数；**用过的序号不再给**：这台机器建过的、或关键帧/编译行/冲突/帧覆盖/成对层级里还提到的键都跳过，删掉的
  对象留下的已确认行和冲突不会挂到新对象上），`cls` 是任一类别或 `other`，`attrs = {"context": true, "label": 自由文本（other 必填，其余可选）,
  "added_by", "added_at"}`（可选 `note`）；没有状态事件、动作、关系，从不 implied，不在日志里；`is_extra` 为假
  （它不是机器的零件）。判断：`model.is_context` / `is_context_key`（键前缀），`machine_only` 去掉它们。
- **凡是走机器零件的地方都跳过它**：状态机不给它状态（`initial_state` 跳过；于是 `needs_geom`、任务卡、
  `missing_shape`、`Space` 的拒绝理由、`cli check`、✂ 行都没有它），`status` 的实例数、关键帧数不算它（单列
  「框外零件」），Steps 模式的动作/关系编辑器看不到它（实例表最下面单独一块「框外零件」：可删、名字可改；
  标注模式里建的、撤销的，回到 Steps 时这一块单独重读，不动 Steps 里没 Apply 的修改。删除连同所有视角的形状
  直接写库，有已确认行时先问一次（几帧会复检开冲突）；删除后标注模式的撤销记录清空，和 Apply 一样），
  约束图（`settled_instances`）、`real_instances`、`implied`、关系启发式、层级地板规则（U17）、合并（拒绝）、
  `T` / `Shift+T`（拒绝，说它没有状态 / 不在步骤表里）、检测器"已画过"的跳过、差异图/检测器的提示框（SAM 不带
  框，`Shift+C` 拒绝）、`Shift+A` 采纳草稿（拒绝）、VLM 导出（`DesktopCtx` 把它和草稿一样拿出去，帧行里也去掉）。
  `import-logs --force` 不删它。
- **新建**：画布右键「框外零件…」，或 Steps 的「＋ 添加零件」对话框里的「框外零件…」（先回到标注模式）：选类别
  （+「其他」）、名字、备注。一条 `add_context_instance` op_log（逆操作删除），撤销栈上一个 `add_context`：
  `Ctrl+Z` 把它连同之后没撤的形状一起拿走（`remove_context`：各视角关键帧、层级条目、成对层级、帧覆盖、缓存行；
  已确认的行不动，复检时按"零件不在了"处理），重做原样放回。建好即选中、开编辑层：画笔/多边形/圆/SAM 都行，
  `Enter` 照常提交关键帧（自己的链 `placement = context`，默认锚在当前帧，倒序往后的帧带着它）；`Ctrl+K`、
  `Alt+Enter` 照常。工具面板不加按钮（U13 的高度）。
- **不在这一帧**：选中它按 `I` =「不在这张里」（标签 `out_of_view`，这一帧不出像素，同零件合照的看不见；
  `Alt+Enter` 画的单帧形状留在覆盖里，撤回后又显示，`I` `I` 原样往返），再按撤回；
  `Ctrl+I` 对一段帧（本位姿段）一次标「不在」或撤回（一个 `set_frame_overrides` op）。实例表写「不在」。
  这一帧没有它的形状时 `I` 拒绝（本来就不在）。
- **编译**：`gather` 把这一帧有形状适用的框外零件加进 `needs`，`placement = context`，自成一组合成：
  组内按层级里的先后（画的先后）遮挡，`L` 只在它们之间有效（和机器零件之间的层级手势拒绝）；和机器零件的像素
  互不遮挡。行照常写入、`Space` 时随帧冻结、像素变了照常复检（在已确认帧后面重画会开冲突，和别的零件一样）；
  **缺了从不是问题**：没有形状适用的帧根本没有它。
- **导出**：COCO 类别 = 它的类别（`other` 单独一个类别，id = 类别数 + 1，只在有它的文件里列出），
  `attributes.context = true`、`label`、`instance_key`，`state`/`placement` 为 `null`；`--roi-crop` 时只保留和
  ROI 相交的（裁到 ROI 里）。`export-coco` 的摘要行单独说有几条。VLM 不导出它。
- **零件合照**也可以画（摆照片的桌上另有东西），规则相同。

### 3.3 编译器（纯函数、可单测）

对视角 v、逻辑步 k：

1. `state(k)` = 初始状态 + 所有 step ≤ k 的事件（父零件 `removed` 时，`attached` 的子零件自动 `removed`）。
2. `needs_mask(k)` = （`placement=in_chassis` 且 `TrackingPolicy` 要求掩码的实例）∪（`placement=on_bench` 且本视角有堆放区 ROI 的实例，几何类型可为框）。
3. 对每个 `i ∈ needs_mask(k)`：在同一位姿段内取 **`anchor_step ≥ k` 中最小者**对应的关键帧（关键帧 j 适用于 (上一个锚点, anchor_j]）。若无 → `missing_shape`：机箱内实例阻塞该帧确认；堆放区实例只产生提示并使该帧 `bench_annotated=false`。
4. 形状经 `T_k`（最近邻）变换到帧坐标 → `A_i`。
5. `V_i = A_i − ∪{A_j : j 在 i 之上}`，逐对判断：有 `PairOverride` 用它，否则用 `ZOrder`。多部件实例按部件分别参与；桌面上的零件与机箱内零件不重叠，层级只在彼此堆叠时起作用。
6. `V_i = V_i − OccluderMask_k`；若有 `FrameOverride`，以其为准。
7. 输出 `V_i`、`A_i` 引用、**遮挡比例** `1 − |V_i|/|A_i|`、派生的 `visibility`（无覆盖时：遮挡比例 < 0.3 → visible，0.3–0.95 → occluded_partial，≥ 0.95 → occluded_full；最短边 < 6 px → too_small，6–12 px → visible_tiny；`FrameOverride.visibility` 优先）与**输入哈希**。

**关键帧与标注方向**：
- 实例寿命由步骤表预先确定，因此首次绘制时默认锚点 = 该实例在本位姿段内最后一个需要掩码的逻辑步。
- 一个实例可以有两条关键帧链：`installed` 链（移除步之前）与 `detached` 链（移除步及之后），锚点机制自然区分。
- 在第 j 步"拆分关键帧"时，新形状作用于**当前浏览方向**一侧：倒序时新关键帧锚点 = j；正序时原关键帧锚点改为 j−1、新关键帧继承原锚点。

### 3.4 真值表 `CompiledMask`

| 字段 | 说明 |
|---|---|
| 键 | (desktop, view, step, instance) |
| `visible_rle`、`occlusion_ratio`、`placement` | 可见掩码（原图坐标）、遮挡比例、installed/detached |
| `status` | `auto`（随输入刷新）/ `verified`（整帧确认后冻结） |
| `input_hash`、`verified_by`、`verified_at` | 溯源 |

规则：

- 输入变化时，只刷新 `auto` 行。
- 冻结行的重编译结果与冻结值比较：**容差对称差**（忽略边界 2 px 以内的差异）> max(2% 面积, 20 px) → 生成冲突，进入冲突队列（保留旧值 / 接受新值 / 编辑），**绝不静默覆盖**。
- 向已确认帧新增或删除实例 → 该帧降为"需复核"。
- 导出只读 `CompiledMask`，报告 verified 比例与质量等级。

## 4. 标注流程与界面

### 4.1 每台机器的工作单

| 阶段 | 内容 | 预计耗时 |
|---|---|---|
| S0 自动准备 | 索引、缓存、选图检查、ROI 建议、步骤表草稿、差分热图 | 无人工 |
| S1 步骤与实例核对 | 每行显示扫描仪第 k−1/k 帧缩略图，预填动作/目标/工具/难度；实例表填父零件、`socket_host`、`cable`、角色、头型；失败步填原因 | 已有模板 10–15 min；机型族首台 30–45 min |
| S2 扫描仪倒序标注（gold） | §4.2 | 2–2.5 h（模型辅助后目标 1.5 h） |
| S3 OAK1 倒序标注（gold） | 与 S2 同一流程，在 OAK1 自己的图上从头画：本视角位姿段/ROI → 任务卡 + 本视角差分 → SAM/人工 → 确认。种子机器之后由本视角检测器出初稿 | **待试标实测**（v1.4 的 0.6–1 h 以迁移为前提，已作废；先按与 S2 同量级估计） |
| S4 OAK2 倒序标注（silver） | 同上；另有堆放区 ROI：起点帧画出全部已拆零件的框，倒序每步少一个框；操作者遮挡用遮挡层 | 待试标实测 |
| S5 RealSense（bronze） | 本视角检测器预标（种子机器人工标）+ **帧级**验收，不逐实例确认；最短边 < 6 px 标 `too_small` | 待实测 |
| S6 约束图 | 规则/模板实例化 → 接受/拒绝 → 校验（§7） | 已有模板 10 min；首台 30 min |
| S7 质检与冻结 | 自动检查全部通过、冲突清零、标记完成 | 5–10 min |

**顺序**：所有机器先做 S0–S2 + S6（扫描仪 gold + 约束），按机型族分批（大族先做，模板尽早复用）；约 8–10 台后训练模型；S3–S5 在模型可用后按视角分批进行。

### 4.2 倒序标注（S2，其余视角同理）

1. **起点** = 该视角最后一个可用帧；在起点帧画出所有需要掩码的实例（若该视角有堆放区 ROI，则为堆放区内每个已拆零件画框）。新画的实例放在本位姿段层级的最上层，只有两个**地板层**例外，与画的先后无关：`chassis` 放最底层，`motherboard` 紧贴最低的 `chassis` 之上（没有机箱时放最底层）（v1.16）。
2. **从第 k 帧退到第 k−1 帧**时，任务卡列出动作 k 引起的变化。**任务卡属于屏幕上的这一帧（k−1）**：卡上要画的形状都画在当前图像上，"已完成"按当前帧判断；差分热图 = 当前帧（k−1）对刚完成的第 k 帧；`Tab` 闪切到第 k 帧（`Shift+Tab` 闪切到第 k−2 帧）。（v1.4 澄清：计划里曾写成"第 k 帧的任务卡描述去往 k−1 的工作"，那样零件在第 k 帧已被拆下，无法在该帧提交。）
   - `removed → installed`：新增机箱内形状，默认放最上层（地板层见第 1 条）；同时列出随它一起装回的附着子零件；若该零件在堆放区有框，则它从堆放区消失（on_bench 链在 k 结束）；
   - `open → closed`、`unplugged → plugged`、`displaced → installed`：在 k−1 处拆分关键帧；
   - `loosened → fastened`：只改状态，形状沿用；
   - `dupli`：整帧复制，一键确认；`failed`：无状态变化，一键确认（但可标记 `in_progress`/手入镜）。
3. 画布叠加差分热图；点击 → SAM（在原分辨率裁剪窗推理）→ 编辑 → Enter。
4. 处理差分中未被任何事件解释的明显区域：拆分关键帧 / 画遮挡层 / 标记忽略。
5. 空格确认本帧 → 写入 `verified` → 下一帧。

**缺帧处理**：扫描仪缺第 k 步时，S2 跳过该帧掩码，状态与锚点按逻辑步照常；其他视角对无扫描仪对应帧的步回退为原生倒序标注。

### 4.3 编辑语义

每次像素编辑必须明确作用范围，画布下方显示"影响 N 帧"缩略条：

| 范围 | 含义 | 默认触发 |
|---|---|---|
| **改形状关键帧** | 修改当前生效的关键帧，影响其适用区间内所有帧（浏览方向上已走过的也改，已冻结的行会重新检查） | 当前帧就是这一版的起点时 `Enter`；别处 `Ctrl+Enter`「改全部」（v1.14） |
| **改层级** | 写 `PairOverride` | 画笔加像素落入 B 的形状 → 提示"把 A 放到 B 之上？"；橡皮擦掉 A 中与 B 重叠的像素 → 提示"把 B 放到 A 之上？" |
| **单帧覆盖** | 写 `FrameOverride`，只改这一帧 | 按住 `Alt` |
| **拆分关键帧** | 从当前步起按浏览方向生成新版本 | `Enter`：编辑像素不落在其他实例形状内、且生效版本从已走过的帧延续过来时的默认（v1.14；`Ctrl+K` 同键） |

- **`Enter` 默认「从这帧起」**（v1.14）：标注员倒序走、边走边确认，第 k 帧改形状的意思几乎总是"从这帧起"。生效版本在浏览方向上已走过的帧里也生效（倒序：锚点在 k 之后，且其间有该零件要几何的可标注帧；正序镜像）时，`Enter` 写拆分关键帧，走过的帧编译结果、复核状态不变、不生成冲突；生效版本就从 k 开始、零件在这里第一次画、或在零件合照上时，`Enter` 写改形状关键帧。✂ 行上没改像素的 `Enter` 只切开版本边界（切开拷贝上拒绝）。
- **并入上一版**（v1.14 评审）：当前帧就是这一版的起点、而浏览方向上身后的帧仍用上一版（刚由 `Enter` 拆出，或第一次画在这帧而上一版延续在身后）时，`Ctrl+Enter` 把形状（编辑层；没改像素时是这一帧存着的这一版）写进上一版的关键帧（全部部件）、删掉这一帧自己的这一版，一个 op、一次撤销两者复原；上一版的已冻结帧照常复检，有已冻结帧时先问；这一帧和身后的帧之间隔着状态边界（✂）时拒绝；身后没有上一版时等同 `Enter`。只在倒序浏览时成立。
- 画笔/橡皮/顶点编辑**绝不触发模型重推理**。
- 会影响已冻结帧的修改，先提示"将产生 N 个冲突"：`L`（改层级）与 `Ctrl+Enter`（改全部）第一次按只在提示条列出影响的帧和其中已确认的帧，再按一次写入，`Esc` 取消。

### 4.4 审阅模式

- 逐帧浏览（上下键），显示可见掩码轮廓、状态标签、问题列表；Enter 接受整帧、`R` 标记返工。
- 入口：冲突队列、需复核队列、缺形状队列、未解释变化队列、**可见性审查队列**（v1.24）。
- silver 视角的核验（S4/S5）主要在此模式完成：模型初稿 → 逐帧接受/修正。
- **可见性审查**（v1.24，U24，第五个队列 `visibility`）：标注时不处理可见性标签（标注模式没有可见性键，编译器自动派生；`` ` `` 被线挡住照旧在画的时候说），最后在复查模式**按视角**逐条核对。队列 = 该视角**已确认帧**里所有 (帧, 零件) 中编译出的 `visibility` 不是 `visible`、或带手动标签 / 遮挡原因的行（自动的遮挡、`too_small` / `visible_tiny` / `out_of_view`、被线挡住、手动标签），减去已盖审查戳的；框外零件、`ignore` 步、零件合照不审。按零件分组、按步排序；同一零件在相邻的可标注帧上标签、原因、手动/自动和遮挡它的零件都相同的压成一段：「ram_latch.03 第 1–13 帧 · occluded_full（被硬盘支架挡住，自动）」/「cpu.01 第 13 帧 · occluded_full（原因: 线缆，手动）」。遮挡它的零件由存储的确认行求出：同一绘制组（placement）里、可见像素落在它这一帧所用关键帧形状内的零件（即层级和成对覆盖的结果），加上该帧的手 / 工具遮挡层；只用游程运算（位姿变换为恒等时不解码），每行按 (步, 零件, input_hash, 标签) 缓存，不编译。选中一条 = 跳到那一帧（经同一道闸）并在实例表选中零件（OAK / RealSense 上主视角小窗跟着）。判定（只在复查模式）：`Space` 确认（按计算，`Shift+Space` 同）；`1`–`7`（`Ctrl` 同）手动设标签，`Ctrl+V` 换下一个；`` ` `` / `` Shift+` `` 被线挡住 完全 / 部分；`Z` / `Shift+Z` **角度看不到** 完全 / 部分（`occluder = viewpoint`，§6.2）。一行是签名相同的一段，**每个键都作用于选中的整段**（40 帧的一段也只按一次 `Z`），答完选中下一条；一段里只有某一帧不同时，面板右上切到「按帧」（一行一帧，即不压缩的队列；默认「按段」），选那一帧再按。面板上写「还要审 n 段 / m 帧（已审 r / t 帧）」。每次判定是一个可撤销 op（`review_visibility`，覆盖这一段的每一帧；复查模式里 `Ctrl+Z` / `Ctrl+Y` 可用），带每帧审查戳的前后和（改标签时）帧覆盖的前后；改标签的判定按 U15 的路子、逐帧：先把这些帧重比一遍（原有差异开冲突、不代签），写入后以这位标注员的名义接受只差可见性的冲突，帧保持已确认，撤销同样；标签让确认时为空的可见掩码露出像素的，只代签屏幕上这一帧，其余帧留冲突给 Review（状态栏说明）。哪一帧不能带完全 / 部分（没形状、在台面上、已拆下）就整段拒绝并写出是哪几帧。审查戳写在 `instance_frame_flags.difficulty_flags_json`（每 (帧, 零件) 一行，原有表、无迁移）：`{"vis_reviewed": true, "by", "at", "verdict": "computed|label|cable|viewpoint", "visibility", "occluder"}`，后两项是审时的标签和原因——标签之后变了（接受了冲突、重画）这一行就回到队列。队列只在复查模式显示时才读（每次写库才重建一次）。面板标签页写剩余行数，上方一行「还要审 n 条（已审 r / t）」，空了写「可见性审查完成」。`status` 每视角报「可见性审查 r/t」；`check` 不报新东西；COCO 导出 `attributes.visibility_reviewed`（按审查戳且戳覆盖当前标签和原因）。

### 4.5 界面布局

- **顶部**：机器选择；视角切换（1–4）；模式（步骤表 / 标注 / 审阅 / 约束 / 质检）。
- **左侧**：纵向时间轴缩略图（灰=未标、黄=自动未确认、绿=已确认、红=冲突/需复核）。
- **中间**：画布——打开即缩放到 ROI；滚轮缩放，>400% 显示像素网格；小地图；掩码填充/轮廓切换与透明度；**`Tab` 在第 k 与第 k−1 帧之间闪切对比**；可并排显示另一视角的同一步作参考。
- **右侧**：任务卡；当前帧实例列表（层级拖拽、显隐、状态标签、`detached` 标记）；属性面板。

**主视角（v1.23，U23）**：上面"并排显示另一视角的同一步"落成一个停靠窗。扫描仪视角先标，之后标 OAK1 / OAK2 / RealSense 时总在找任务卡上那个零件在哪；在 `oak1`、`oak2`、`rs` 的拆解帧上（标注、复查模式）右栏最下面有「主视角」：同一步的扫描仪帧（这一步扫描仪缺图或是 dupli 步时用更早的最近一帧，标题写「（第 k 帧扫描仪没有图）」/「（第 k 帧是重复帧）」），裁到目标零件的扫描仪掩码周围（零件约占一半，裁剪框至少是帧长边的 10 %），轮廓用零件自己的颜色（和画布同色），零件里离边最远处一个点；标题「主视角 第 k 帧 · <名称>（<状态>）」，状态取所示那一帧。目标与按键作用的零件同序：正在画的 → 实例表选中的（含 Removed 行）→ 任务卡当前行；任务卡行不是零件（dupli 帧那一行）时只显示画面。单击在裁剪和整帧之间切换（整帧画零件外框，扫描仪位姿段有 ROI 时淡淡画出），滚轮缩放裁剪；多块的零件按并集外框裁。没有轮廓时显示整帧并写原因：「扫描仪视角里这一帧没有它」（存着的行没有形状）、「扫描仪视角里还没画它」（扫描仪视角没有它的关键帧或单帧形状）、「扫描仪视角还没标注，只显示画面」（这台机器扫描仪视角什么都没画）。**数据**：轮廓读真值表里那一帧、那个零件**存着的** `compiled_mask` 行（不重新编译，不判断是否过期）；那一帧没有存储行时整帧编译一次（`TruthService.compile`，不写库），各零件的轮廓都留下，直到扫描仪视角的输入（关键帧、单帧形状、层级、状态事件、实例、步骤表、帧行）变了。画面从本地缓存按长边 1024 px 解码（JPEG 由解码器直接缩小），内存里留最近 20 步；离线缩略图（192 px，裁到机箱）太小，不用。**代价**：小窗隐藏（关掉、扫描仪视角、零件合照、Steps）时什么都不读；同一帧同一零件、同一编辑轮次不重读。实测：12 MP 扫描帧某一步第一次显示约 60 ms，画面已缓存约 1 ms，没有存储行时约 400 ms（一次）；1600×1600 为约 16 ms / 1 ms / 90 ms，真实 D13 扫描帧解码约 30 ms。**停靠窗**：默认在右栏底部约 300×260（工具面板在画布左边，高度不变），可拖动、浮动、关闭；位置随窗口布局存进 `tda_app.ini`，开 / 关另记 `locator/open`（默认开）——关掉后换视角、重开程序都不再出来，顶部「主视角」按钮（只在这三个视角上可点；v1.28 起扫描仪视角上也可点，见下段）或窗口的停靠菜单再打开。没有快捷键。

### 5.1 交互式分割（MVP）

- **SAM 2.1 Hiera-L** 图像预测器常驻后台线程；输入为视野裁剪窗（原分辨率）；支持点、框、`mask_input`。
- **两个解码头（v1.19，U19）**：实验 L5 用标注员已确认的扫描仪可见掩码微调了提示编码器 + 掩码解码器（图像编码器冻结；配方 v2，D2/D3/D4/D13 训练，D5 盲测：小件四组宏平均 IoU +0.10、边界 F +0.13，螺丝边界 F 0.82→0.93，接口单点 IoU 0.31→0.58；只有"大件、只有点"一格 −0.021 未过门槛）。`SamService` 只有一个图像编码器、一份缓存嵌入，挂两套（提示编码器，掩码解码器）：原版与微调版。微调版是 `sam2.1_tda_head_f5_v2.pt`，只存与原版不同的 141 个张量（4.09 M 参数，16 MB，旁边 manifest 记两份源权重的 sha256 与训练来历），加载到原版两模块的副本上，并核对原版权重的指纹。每个提示只由一套回答（`SamResult.head`）：有框（检测器框、差异图框、`X` 拖框、点 + 框）→ 微调；只有点且正在画的实例属于 `configs/sam.yaml` 的 `stock_point_classes` → 原版（名单每一项都注明理由：扫描仪面积带上限 > 20 000 px 的 7 类；裁定点名、没有面积带的大件 chassis、expansion_card；L5 两台留出机（各自那一折的模型）上微调头单点都更差的 ram_module（−0.096 / −0.023）、drive_latch（−0.027 / −0.191））；其他只有点（含类别未知、框外零件 `other`）→ 微调；纠错点击（`mask_input`）回到给出该掩码的那一套；`C` 轮换回答那套的三个候选。L5 也训练了解码器的 `conv_s0`/`conv_s1`，而 `forward_image` 用它们投影编码器的两层高分辨率特征后才缓存，所以两套共用图像嵌入，高分辨率两层由各自的卷积从同一份编码器输出投影（每个裁剪窗多约 0.1 ms）；与把完整 f5_v2 权重当整个模型加载的输出逐位相同。配置或头文件不可用 → 一条 WARNING，全部用原版，状态栏「SAM ready」后注明；`TDA_SAM_HEAD=off`（或另一份配置）覆盖。
- 显存预算：SAM 约 4–6 GB，其余留给训练。
- SAM 3 概念提示列为 P2 试验。

### 5.2 训练闭环（约 8–10 台扫描仪 gold 后启用）

- v1 只接一个框架：**Ultralytics YOLO26-seg**。
- 训练数据：已确认的 ROI 裁剪 + 可见掩码（类别 = 23 类；`detached` 作为附加属性，训练时可选并入类别）；每新增约 10 台重训，子进程运行，限制批大小避免与 SAM 争显存。
- 用途：扫描仪起点帧提议；其他三视角的批量初稿（预测框 → SAM 精修边界 → 可编辑初稿）。
- **视角冷启动**：每个新视角先人工完成 3–4 台（任务卡 + 本视角差分 + SAM），加入训练集后再对该视角批量预标（跨视角域差大；v1.5：不用单应提示）。
- 多框架对比（RF-DETR-Seg、EoMT/Mask2Former）只作论文基线。

### 5.3 效率记录

- 每个形状保存初稿与终稿，记录初稿 IoU、编辑操作数、耗时。

### 5.4 精度目标

- 边界误差：扫描仪 ≤ 2 px，OAK ≤ 3 px，RealSense ≤ 1 px（大零件）；`too_small` 实例不计。

### 6.2 状态集与默认追踪策略

| 类别 | 状态（需要掩码的状态加粗） |
|---|---|
| `screw` | **fastened** / **loosened** / removed（桌面可见时可有 `detached` 形状） |
| 各类 latch、`cpu_socket_lever`、`cable_clip` | **closed** / **open** |
| `cover` | **closed** / **open** / removed（同上可 `detached`） |
| `connector` | **plugged** / unplugged（不追踪）/ removed |
| 部件类（含 `drive_cage`、`cooler_bracket`、`misc_part`） | **installed** / **displaced**（画一次新形状）/ removed（桌面可见时可有 `detached` 形状） |
| `chassis` | **present** |
| 虚拟节点 `cable:*` | routed / released（无掩码） |

**帧级可见性 `visibility`**（每实例每帧，自动派生、可人工覆盖；v1.24 起人工覆盖只在复查模式的「可见性审查」里做，§4.4）：`visible` / `occluded_partial` / `occluded_full` / `out_of_view` / `too_small`（只保留中心点）/ `visible_tiny`（只导框）/ `motion_blur`。它同时是 V14"本视角能否判断"任务的真值来源。

**遮挡原因 `occluder`**（v1.15，U15「被线挡住」）：线缆不标注，零件在原位却被线（或别的不标注的东西）挡住时，人工可见性标签带上原因，存在 `FrameOverride.occluder`（`cable` / `other_unlabeled`，界面只写 `cable`）。完全 = `occluded_full` + 空的可见掩码（编译出的可见部分为空，形状照旧——可以从别的帧带过来）；部分 = `occluded_partial`，编译器的可见像素保留。只有该帧有掩码形状、零件在原位（不在台面上、未拆下）时才能标完全/部分；**撤回从不拒绝**：该帧已不能带它已有的标签时（步骤表改了、形状没了、零件到了台面上），下一次 `I` 直接撤回（不经过部分），`Ctrl+I` 撤回对任何帧都行；`cli check` 把所有不能带的原因记为 `occluder_without_shape`。完全替换掉该帧手画的单帧掩码（可撤销，状态栏说明）；在完全的零件上「只改这一帧」画出像素，标签改为部分、原因保留。已确认的帧上，这个标签就是标注员对这一帧的说法：写入后重新编译，只差可见掩码和可见性标签的冲突以这位标注员的名义接受，帧保持已确认（撤销同样）；只签这次写入造成的差异：写入前先把范围内已确认的帧都重新比一遍，已有的差异（例如别处重画、还在复检队列里）先开冲突、留给 Review，不代签；比过的帧移出复检队列。也不代签"露出"的像素：确认时可见掩码为空（完全）、现在要显示像素（部分 / 撤回）的帧，只签当前这一帧，其余帧留着冲突、状态栏说明（撤销完全、中间没改过时露出的正是当初确认过的像素，照签）。数字键不变。完全标在状态边界帧上时，该帧的 ✂ 行算完成（看不见就没有可画的新形状）。导出：COCO 每条标注带 `attributes.occluder`，带原因的标注另带 `amodal_segmentation` / `amodal_bbox`（v1.26 起每条掩码标注都带，见 §8.1），完全的那条照样导出（空的可见分割 RLE、面积 0、`bbox` 为完整形状的框、`iscrowd: 1`——COCOeval 既不要求可见掩码检测器找到它、也不因此扣分）；VLM 的 `observe` 证据带 `occluder`，V14 弃答写"在原位，被线缆挡住"。

**角度看不到 `viewpoint`**（v1.24，U24）：`occluder` 的第三个取值。零件在原位、什么也没挡住它，只是这个相机从它的位置看不到（OAK / RealSense 的侧面视角常见）——和被线挡住是两个原因，分开记。只在复查模式「可见性审查」里设：`Z` = 完全（`occluded_full` + 空的可见掩码，形状照旧），`Shift+Z` = 部分（`occluded_partial`，编译器的可见像素保留）；规则和被线挡住相同（要有该帧适用的掩码形状、在原位，台面上 / 已拆下的拒绝）。导出：COCO `attributes.occluder = "viewpoint"`，带 `amodal_segmentation` / `amodal_bbox`，完全的照样 `iscrowd: 1`；VLM `observe` 证据带 `occluder`，V14 弃答写 "X is in place, not visible from this viewpoint, in view …"（在原位，从这个视角看不到）。标注模式的实例表 / 任务卡把它写成「角度」/「角度看不到」，不写线挡。

| 记录位置 | 内容 | 用途 |

| `screw.role/head/head_source/captive` | 紧固件属性及头型判读来源（记录 / 图像） | 工具问答（视觉判别版）、连带事件 |

| `Instance.removal_direction` + `PoseSegment.chassis_frame_in_image` | 名义拆卸方向 + 机箱坐标系在图像中的朝向 | 操作方位问答、空间关系程序生成、机器人侧复用 |

| `Action.failure_reason`、`Action.difficulty`、`Step.notes` | 失败原因、难度、操作者意图/自述 | 失败案例、难度问答 |

**由其他数据推导、不单独存储**：`occluded_by`（编译器输出，导出时物化）、`same_group`（group_id）、`requires_tool`（head 属性）、空间邻接与相对方位（掩码几何 + `chassis_frame_in_image`）、`supports`/`part_of`/`secures` 等反向或同义边、"合法动作集合"、进度与剩余步数（约束图 + 状态）。**数据库不存"合法动作集合"，但导出的训练/评测 JSONL 必须物化它并写入 `graph_version`，保证评测可复现。**

### 7.2 硬约束语义

对目标执行 `remove` / `displace` / `open`（及对螺丝 `unscrew`、对接口 `disconnect`）之前，另一节点必须处于指定状态：

| 类型 | 所需状态 |
|---|---|
| `fastened_by(X, screw)` | screw ∈ {loosened, removed} |
| `connected_to(X, connector)` | connector ∈ {unplugged, removed} |
| `locked_by(X, latch)` | latch ∈ {open} |
| `covered_by(X, Y)` | Y ∈ {open, removed, displaced} |
| `blocked_by(X, Y)` | Y ∈ {removed, displaced, released} |

**每类边挡住哪些动作（v1.6，取代上面"之前"一句的字面含义；实现见 `tda/core/graph_rules.py`，检查器、合法动作集合、规划器读同一张表）**：

| 类型 | 挡住的动作 | 理由 |
|---|---|---|
| `fastened_by` / `locked_by` | remove、displace、open | 拧着/锁着的零件动不了，但仍可以在它上面拔插头、拧别的螺丝 |
| `covered_by` | 全部 | 被盖住就够不着 |
| `connected_to` | 仅 remove | 线还插着时可以把零件挪开（薄机箱的电源必须先挪开才够得着插头），不能拿走。旧规则"挡全部"在 66 份日志上产生 34 条误报 |
| `blocked_by(mode=cable_tension)` | 仅 remove | 被线拉住：能动，拿不走 |
| `blocked_by(mode=physical_path)` | remove、displace | 挡在路径上 |
| `blocked_by(mode=tool_access)` 或方式缺失/未知 | 全部 | 工具够不着；未知按最保守处理 |

被**拆走**（或不存在）的阻挡物满足任何一条边。`necessity=recommended` 的边是**偏好**：不参与合法性、不参与死锁判定；规划器能遵守就遵守，遵守不了就忽略并标记 `relaxed`（建议只能改变计划的顺序，不能让计划不存在）。关系行的 `status ∈ {proposed, accepted, rejected, accepted_orphan, rejected_orphan}`：规则边不可手改，只能接受/拒绝（存为 `source=override`）；规则不再推导出该边时决定变为孤儿（不生效、可见、可转为手工边），规则回来时决定原样恢复；`rejected` 与两种孤儿状态不生效。`graph_version` 的摘要包含 `status`（审过的图是另一个版本）。S1 的 Apply 在同一事务里用与命令行相同的函数重推本机规则边。

**接口规则**：移除部件 X 之前，所有满足 `socket_host = X` 或 `cable.owner = X` 的接口必须已断开（SATA 数据线两端独立；PSU 线束的所有插头都要求已拔下才能取 PSU）。

### 7.3 生成

1. **属性规则**（预计覆盖约 90%）：`screw.fastens = X` → `fastened_by(X, screw)`；接口规则 → `connected_to`；`latch.of` → `locked_by`；`cover.of` → `covered_by`；`cable_clip.holds` 的线缆若阻挡目标 → `blocked_by(目标, cable, mode=cable_tension)`；固定模板边（如 `cpu covered_by cpu_cooler`、`cpu locked_by cpu_socket_lever`）。
2. **机型族模板**：同族共享"零件槽位图"，实例化到每台机器；每个族的首台人工补全后保存为模板。
3. **人工**：剩余 `blocked_by` 在约束面板添加。

每条边记录：来源（rule / template / manual）、证据（步骤 id）、状态（proposed / accepted / rejected）。

### 7.4 校验

- **图无动作死锁（v1.6，取代"图无环"）**：节点是动作 `(verb, instance)`；动作 `(v, T)` 依赖每条挡住 `v` 的生效必要边 `(T, B)` 的清除动作；清除动作是**一组**候选（凡能让 B 进入该边接受状态的动词，最后再加"拆走 B"——若其类别可拆），对边取"与"、对候选取"或"；死锁 = 这张图里从某个零件的拆除目标可达的环（`graph_plan.find_deadlocks`，全代码唯一的定义；性质：无死锁且无死胡同 ⇔ 每个零件都排得出拆解计划）。零件层面的环不一定是死锁：`fastened_by(支架, 螺丝)` + `blocked_by(螺丝, 支架, physical_path)` 可解，因为"拧螺丝"不被后者挡。面板的任何编辑与 Apply 时的规则重推都不得存入死锁（拒绝并指出环与解法）；命令行对已含死锁的库只报告（退出码 1），不擅自修复。**死胡同**（某条边没有任何清除动作，如 `locked_by(X, 机箱)`）不是错误，但必须可见：页签、待确认问题、报告各列一处。
- 每个成功动作执行前一刻，其前置条件全部满足。
- 每次失败尝试执行前一刻，至少一个前置条件未满足（含虚拟线缆节点），且与 `failure_reason` 一致。
- "合法动作集合"为计算量，不存储。

## 8. 导出与 VLM 层

**确定真值原则（v1.6，适用于一切依赖约束图的 VLM 任务）**：约束图记录的是物理**必要**边，可能不完整。因此——图**禁止**的一定做不了；图**允许**的只是上界；日志**演示过**的一定做得了；**状态上已不适用**的（目标已处于该动词的终态、已不在场、已随父件离开）一定做不了，且必须看图才能判断。标签只发布这四类确定的真值，并写明来源 `truth_source ∈ {demonstrated, graph_blocked, state_inapplicable, failed_attempt}`：V4 正例 = 演示过的下一步，反例 = 被图挡住（列全部未满足的必要边）或状态上不适用，按"同动词同类别 → 同动词 → 同类别"匹配采样，约 1:1，指标为按动词宏平均的准确率；V5 的标签是 `{must_include（演示过的）, must_not_include（确定做不了的）, permitted_upper_bound}`，指标为演示召回 + 被挡率，**从不**声称列出了"物理上可能的全部动作"；V6 选项 = 1 个演示过的 + ≥2 个确定错误的 + 标明"未知"的干扰项（种类只在标签侧）；V16 有效计划 = 日志后缀，无效计划 = 违反必要边的篡改（交换、移动、替换），1:1。没有 `graph_version`、没有任何生效边、或含死锁的机器不出这些题；日志含未解析目标（`?`）的机器不出 V10；日志与图矛盾的步骤（当前 9 步 / 15 条边）不作真值。每条记录分 `prompt`（模型可见：task、不透明图像 id、question、options）与 `label`（其余全部）；图像 id 与记录 id 为加盐哈希，映射在标签侧的 `*.images_manifest.jsonl`；导出自带"只看题面"的分类器上界表（动词、类别、动词+类别、模板），V4 各项须 ≤ 65 %。V15 不用任何几何，只用各视角自己已确认的 `visibility`。

### 8.1 CV 导出

- 每视角 COCO 实例分割（可见掩码 RLE；近似完整形状作为扩展字段并带 `amodal_complete`；`detached`、`occlusion_ratio`、状态作为附加属性）；全图与 ROI 裁剪两种坐标版本。
- **完整形状（amodal，v1.26，U26）**：**每条掩码标注**都带 `amodal_segmentation`（压缩 RLE，和 `segmentation` 同一坐标：全图，或 `--roi-crop` 时裁到 ROI——完整形状同样裁剪）、`amodal_bbox`（`[x, y, w, h]`，空时 `null`）、`amodal_area`（像素数）；完整形状取编译器的：该帧适用关键帧各部件之并、经该帧配准变换，可见掩码就是从它切出来的，所以 `attributes.occlusion_ratio = 1 − area / amodal_area`。**文件里可见 ⊆ 完整形状**：可见掩码有像素落在编译出的形状外（「只改这一帧」画在别处，或冻结行保留了形状后来挪动前的可见掩码）时，导出 `完整形状 ∪ 可见`，`info.amodal_union_rows` 记条数（`occlusion_ratio` 仍是编译器的；D2–D14 扫描仪 19 条）。该帧没有形状（像素只来自「只改这一帧」的掩码）时按同一条规则 `amodal = 可见`，也计入 `info.amodal_union_rows`；三项为 `null` 只在既没有形状、也没有可见像素时（这样的行不导出）；台面框（`include_boxes`）不是掩码标注，不带。默认开；`export-coco` 加 `--no-amodal` 只去掉 U26 新加的（`amodal_area`，以及没有原因的行上的另两项），被线挡住 / 角度看不到的行照旧带 U15 / U24 写的 `amodal_segmentation` / `amodal_bbox`（§6.2）——所以 `--no-amodal --no-hidden` 除 `info` 外与 U26 之前的文件逐字节相同（D11 实测）；`info.amodal` 记录是哪一种。`info.version` 升为 `"2"`：标注集合变了（多了整个被盖住的行，后面的 id 顺移）。被线挡住 / 角度看不到（完全）的那条照旧：空可见分割、`area` 0、`bbox` 取完整形状的框、`iscrowd: 1`。**被上面标了的零件整个盖住的零件（`occluded_full`、什么也看不见、没有原因）也这样导出**（带三项，`attributes.occluder` 为 `null`）——分层 amodal 数据集要的正是它们；加 `--no-hidden` 不导出，`info.hidden` 记录是哪一种。D3 扫描仪 48 帧：1 504 条（其中 231 条整个被盖住），2.76 MB；`--no-hidden` 1 273 条 2.51 MB；`--no-amodal` 1.82 MB；两个都加 1.68 MB（= U26 之前）。
- 帧级状态 JSON、每机约束图 JSON、步骤/动作表。
- 每条标注带质量等级（gold / silver）与确认状态。
- RGB-D：RealSense 直接可用；OAK1 对齐版本为 P2。
- **划分**：在数据冻结时确定，按机箱平台不相交；导出脚本以 `Desktop.split` 为准。

### 8.2 VLM 样本设计

**设计原则**（以"VLM 需要学到什么"为出发点）：

1. **感知落地**：每个答案都能对应到掩码/框（证据可定位）。
2. **状态与变化**：单帧状态、两帧变化、"无变化"负样本（dupli）。
3. **物理因果**：答案附带结构化推理链（观察 → 适用约束 → 结论），可程序生成。
4. **历史与进度**：从单帧推断已完成动作集合与剩余步数。
5. **可见性诚实**：被遮挡/太小/不在视野时，正确答案是"本视角无法判断"；多视角融合时可判断。
6. **合法性而非唯一性**：下一步/计划类问题以约束图给出的合法集合判分。
7. **困难负样本**：非法动作、不存在的零件、失败尝试、近重复帧、桌面上已拆零件与机箱状态的一致性。

**任务清单**：

能力分层：**L1 感知**（V1/V2/V8）→ **L2 可供性**（V4/V5）→ **L3 规划**（V6/V7/V16）→ **L4 元认知**（V14 可判定性/拒答、V15 跨视角）。L1 是任何数据集都能提供的；**L2–L4 依赖"视角无关的状态机 + 多个可见度不同的观测"，是本数据集独有的贡献**，其边际标注成本接近零。

| 代号 | 优先级 | 任务 | 输入 | 答案来源 | 指标 |
|---|---|---|---|---|---|
| V1 | P0 | 看到了哪些组件、在哪 | 单帧 ROI | 可见掩码/框（含 on_bench） | 集合 F1 + 框 IoU |
| V2 | P0 | 零件状态 / 计数 | 单帧 | 状态 | 准确率 / 完全匹配 |
| V3 | P0 | 刚做了什么（动词、目标、工具） | 第 k−1、k 帧 | 动作 | 各槽位准确率 |
| V4 | P0 | 能否对 X 执行某动作、为什么不能（含反事实：现在直接抽 PSU 会怎样） | 单帧（+历史） | 约束图 + 状态 | 是否准确率 + 阻碍集合 F1 |
| V5 | P0 | 现在能做哪些动作 | 单帧（+历史） | 合法动作集合 | 集合 F1（严格/宽松两组） |
| V6 | P0 | 下一步做什么 | 单帧 + 历史 | 合法动作集合 | 合法率 + 与实际匹配率 |
| V8 | P0 | 指代定位 | 单帧 | 可见掩码 | IoU@0.5 / 点在掩码内（tiny 只算点） |
| V10 | P0 | 已完成了哪些动作（历史推断）、进度分箱 | 单帧 | 状态 → 已发生事件；约束图 → 剩余 | 集合 F1；分箱准确率 |
| V12 | P0 | 两帧之间是否有变化（dupli；P1 加入扫描仪同步连拍作负样本） | 两帧 | dupli / 事件 | 准确率 |
| V14 | P0 | 可判定性 / 拒答：本视角能否判断 X 的状态 | 单帧 | `visibility` + 状态是否由本视角不可见特征决定 | 准确率 + risk-coverage / 过度自信率 |
| V15 | P0 | 跨视角一致性：是否同一时刻同一机器；A 视角被挡的 X 在 B 视角是什么状态；哪个视角更适合回答 | 两帧 | 共享实例 + `visibility` | 准确率 |
| V16 | P0 | 计划验证 / 找错：给定候选序列是否合法、第一处错在哪 | 单帧 + 序列 | 约束图（一半为程序生成的错误序列） | 准确率 + 定位 |
| V7 | P1 | 达到目标的剩余计划 | 单帧 | 约束图 | 拓扑合法性 + 达成目标 + 冗余步数 + 第一处违规 |
| V9 | P1 | 紧固件头型视觉判别（十字/梅花）与所需工具 | 扫描仪/OAK1 局部图 | `head`（仅 head_source=图像的样本） | 准确率 |
| V13 | P1 | 真实失败尝试的解释（5 例，作定性案例） | 两帧 | `failure_reason` + 约束 | 案例研究 |
| V17 | P1 | 堆放区零件与机箱状态一致性 | 单帧（OAK2） | on_bench + 状态 | 集合 F1 |
| V18 | P1 | 操作方位（拆卸方向、相对位置） | 单帧 | `removal_direction` + `chassis_frame_in_image` + 掩码几何 | 准确率 |

- 输入图像：扫描仪或 OAK1 的 ROI 裁剪（V17 用 OAK2；V14/V15 覆盖四个视角）。
- **推理链格式**：封闭操作集 `op ∈ {observe, recall_relation, check_precondition, propagate_state, compare_frames, conclude, abstain}`；每个 `observe` 必须带框/点与 `visibility`；记录 `depth`（推理步数）用于按深度分层评测；自然语言由模板渲染。例：
  `{"task":"V4","answer":{"feasible":false,"blockers":["screw.motherboard.03"]},"rationale":{"depth":3,"steps":[{"op":"observe","target":"screw.motherboard.03","value":"fastened","evidence":{"view":"scan","bbox":[...],"visibility":"visible"}},{"op":"recall_relation","edge":["motherboard","fastened_by","screw.motherboard.03"],"necessity":"required"},{"op":"check_precondition","required":["loosened","removed"],"actual":"fastened","satisfied":false},{"op":"conclude"}]}}`
  评测时除最终答案外报告 **推理链落地准确率**（中间步的框是否正确）。
- **困难负样本**：同机相邻两步（只差一颗螺丝）；同平台不同机器的同一步（防止记忆机器指纹）；"合法但当次没做"的动作作为 V6 干扰项；对被遮挡/已移除零件提问（正确答案为拒答或"已移除"）；同平台但螺丝数不同的计数干扰；用 OAK2 遮挡帧问只有扫描仪能看清的属性。
- 每个任务 5–10 个人工编写的问法模板；评测时要求 JSON 作答。
- 规范格式为统一 JSONL（含物化的合法动作集合与 `graph_version`），再转换为 Qwen-VL / InternVL / LLaVA 格式。
- **测试集**：模板生成 + 100% 人工审核（抽样平衡约 2–3k 条），不做 LLM 改写。
- **评测**：P0 零样本（主流闭源 + Qwen3-VL、InternVL 系列）+ 纯文本基线；P1 人类基线与 LoRA 微调一个开源 VLM；P2 LLM 改写问法（仅训练集）。

## 9. 质量控制

### 9.1 自动检查（S7 必须全部通过）

- 每个动作的目标存在；状态变化合法。
- 每个需要掩码的实例在 gold 视角有生效形状，或 `hidden`。
- 同一帧可见掩码两两不重叠。
- 冲突、需复核、未解释变化队列清零。
- 约束图无环；观察序列合法；失败尝试有未满足约束。
- dupli 帧与前一帧掩码一致。
- **可见掩码为空**（v1.26，U26）：被上面标了的零件（或手 / 工具遮挡层、或人工标签）整个盖住的零件，编译出 `occluded_full`、完整形状有像素——这是分层标注该有的结果，`cli check` 只报一行「n 个零件完全被挡住（正常）：m 个零件帧，不算问题」，不列、不计入问题数、不影响退出码；标了「看不见」（`out_of_view`）的同样不算。可见掩码为空而说不出原因的才是问题（`empty_visible:<零件> (step N): …`）：完整形状在这一帧是空的（没画，或经配准整个在画面外），或标签仍说看得见。标注界面任务卡分开说：整个被盖住的照旧「这一帧里它被完全挡住了」，形状为空的写「这一帧没有它的形状（没画，或整个在画面外）」；`status` 不变。

### 9.2 人工质检与上手

- **标注指南**：`docs/annotation_guide.md`，含编辑语义、状态定义、常见情况示例（从 D13 截图）。
- **同学上手**：先独立标 D13 扫描仪视角，与用户版本比较，掩码 IoU ≥ 0.9、状态一致率 ≥ 95% 后进入生产标注。
- **双标**（P1）：4–5 台扫描仪视角两人独立完整标注，报告掩码 IoU、状态 κ、约束边 F1。

| 冲突风暴（小目标重采样误差） | 审阅负担 | 容差对称差 + 面积/像素双阈值 |
| 其他视角域差导致预标质量低 | 核验变慢 | 每视角冷启动先人工 3–4 台 |
| 四视角容量不足 | 部分视角只有 auto 初稿 | 如实标注质量等级；优先核验测试族 |
| 开发延期 | 压缩标注时间 | MVP 仅扫描仪、功能边标边加、多 worker 并行 |
| 约束图缺边 | VLM 答案错误 | 观察序列 / 失败尝试双重校验；测试集人工审核 |
| 数据损坏 | 返工 | WAL + 每日备份 + 操作日志 |

## 13. 被否决的方案

| 方案 | 否决原因 |
|---|---|
| 继续使用 Label Studio / CVAT / X-AnyLabeling | 按单图设计，无法表达跨步继承、图层、共享实例、状态与约束 |
| 本地网页应用 | 开发量更大，两人轮流使用时收益不足 |
| 每帧独立掩码 | 遮挡需逐帧人工处理，无近似完整形状与自动遮挡关系 |
| 以图层模型本身作为真值 | 修改会静默改变已确认帧 |
| 关键帧使用显式 [a, b] 区间 | 倒序时下界未知，易产生缝隙 |
| 链式相邻配准 | 漂移累积会静默污染整段 |
| 按接口"端点"生成约束 | 会把 SATA 线两端都变成约束 |
| 追踪拔下的接口 | 插头随线缆移动，代价极高而收益低 |
| 桌面零件另设类别 | 检测语义应保持"同类物体"；`detached` 作属性 |
| 52 类细粒度词表 | 样本不足；状态应为属性 |
| 以实际拆解顺序作为约束真值 | 只是合法顺序之一 |
| 预先划分测试集 | 用户决定先全标；划分在冻结时按平台确定 |
