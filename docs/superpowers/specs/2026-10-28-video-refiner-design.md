# 双机位视频精修器

用户授权：直接按推荐的独立桌面工具实现，细节由实现者决定，跳过设计问答。

## Intent

将初筛的动作片段变成人工可精修的工程。以 OAK 原片时间为主轴，在两个机位各定位同一动作瞬间后对齐，后续只编辑一次动作区间，即可导出两个机位的对应片段。默认打开 Desktop 7 的 58 段初稿；用户更正的第六段结束点 288.5 秒必须保留。

## Approaches

采用独立 PySide6 桌面窗口，复用本机 Python 环境，JSON 工程与现有静态图像标注库解耦。集成进主标注程序会改变正在使用的工作流；浏览器方案对本地大文件、逐帧和跨盘读取需要额外服务，暂不采用。用户选择了推荐的独立工具。

## Behavior

- 左侧动作列表，中间双机位原片/ROI 预览，下方局部时间轴、起止点、标签、备注及确认状态。
- 原片可自由定位，片段带前后预览范围，逐帧/慢放/循环；切点使用实际解码帧的时间戳。出点是排他的，设为当前帧后沿，确保眼前这一帧被保留。
- OAK 是主时间轴。同步模式允许两机位独立定位，捕获一对锚点得到 `rs = oak + b`；第二对锚点显示误差，可显式开启线性校正 `rs = a*oak + b`。不使用文件名或录像长度差推断同步。
- 同步预览以 OAK 时钟驱动；每个机位显示实际帧时间。普通播放可以跳过显示帧，暂停和逐帧必须按原始 PTS。RealSense 可变帧率不按平均帧率乘帧号。
- 每机位独立 ROI；支持在完整画面拖框，精确数字编辑及全画幅恢复。默认 OAK 使用已审核 ROI，RealSense 初始全画幅等待用户框选。
- 支持调整/新增/拆分/排除片段、编辑标签/备注、确认、撤销重做、恢复初筛切点。初筛原始字段保留，排序按开始时间；不因重叠自动合并。
- JSON 自动保存与显式保存，原子替换、上一版本备份和单工程文件锁。原初筛清单、原片和标注数据库不修改。可另存、重新定位源文件；改变源文件会清除同步关系和确认状态。
- 导出选择当前/全部保留/已确认片段，双机位同编号 MP4、CSV 和 JSON，包括源起止点、ROI、锚点和变换。导出到 D: 上唯一新目录，取消只影响该次导出并留下未完成状态。
- 双机位导出必须有同步点；任何映射区间超出源范围时明确拒绝，不静默截断。无同步时可仅导 OAK。
- 默认导出无音频、H.264、CRF18；统一 30fps 方便对应播放。启用线性校正时 RealSense 时间轴除以 a，使两份导出均按 OAK 时长播放；映射信息写入清单。帧量化误差控制在一输出帧，清单记录实际媒体时长。

## Constraints

- Windows；Python 3.11；PySide6、PyAV（现有环境已安装）、FFmpeg。所有新文件及临时文件在 D:。
- 原始盘只读；不打开 `annotations/tda.sqlite`；不连接外部服务。
- 功能在 `tda/video/` 中独立实现，通过 `start_video_refiner.bat` 启动。不改变现有标注程序行为。
- 用户标记锚点，不自动猜测同步。丢帧/录像中断不承诺用单一仿射模型纠正，用户需回看中间动作；超出支持范围应显示限制。

## Acceptance

真实 Desktop 7 载入 58 段，逐帧查看/修改/保存/重开/撤销可用；合成不同帧率与非均匀 PTS 视频验证同步数学和成对导出；真实短段导出解码、时长、ROI 验证；界面实际启动检查。新增功能测试和项目要求的回归检查通过后交付。
